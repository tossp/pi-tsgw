# 本地上传维护边界

工具接口、分片协议和恢复流程以源码及相邻测试为准。这里保留不能仅从实现推导的宿主、服务和授权前提。

- 只使用宿主已配置、连接并授权的 ts_oht，不自建 MCP/S3 客户端或凭据管理，不自动注册服务、修改用户设置或借重连绕过禁用与登录。
- 授权对象是文件外传，不是仅读取。文件位于 Pi 运行主机而非浏览器所在机器；不要把 OS 权限、工具权限或输入校验宣传为文件沙箱。
- 宿主默认 MCP 超时可能早于服务完成；接口和就绪等待依据见 Blinko 871、930。需要调整时由用户决定，插件不编辑配置；本地 deadline 和取消均不保证远端停止。
- 恢复凭条不是新建上传授权。结果未知时先核对旧对象，未经明确要求不发起恢复、补偿上传或新对象；恢复前停止其他客户端，不能把进程内锁当跨客户端互斥。
- 服务无按 uid 恢复端点，恢复规划可能创建不同计划；遇身份变化必须拒绝发送字节，不能为了成功擅自接受新对象或清理旧对象。
- 服务的存储访问权限不是按用户隔离；下载 URL 是持有者凭据。inline HTML 等活动内容可能执行，不能只按“私有桶”推定链接安全；重新签名不延长对象保留期。
- 真实上传验收会创建合成对象，必须单独获授权；不因模拟测试通过就声称真实服务已验证，不擅自清理测试对象或改桶生命周期。
