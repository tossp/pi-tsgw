# Magpie 扩展需求分析

## 1. 背景与目标

pi-tsgw 已接入 Magpie 网关，并具备会话追踪和共享目录服务。网关还提供额度、路由及用量信息，可用于回答三个问题：当前任务实际由谁执行、有哪些可用资源、请求在网关中如何归属。

本专题将可扩展能力收敛为可审阅方案。功能应复用 Pi 的认证、模型注册表、协议适配和子代理调度；账户路由继续由 Magpie 负责。

术语见[名词解释](000.名词解释.md)，设计与实施入口分别见 [B00](B00.规划设计.md) 和 [C00](C00.执行计划.md)。

## 2. 功能范围与分期

以下是待确认的分期建议，列入文档不代表已经授权实现。

| 阶段 | 功能 | 预期结果 |
| --- | --- | --- |
| M0 | 状态展示、额度详情、显式刷新 | 能查看当前会话及资源，区分缓存读取和上游刷新。 |
| M1 | 请求归属与用途补充 | 主任务、真实子会话、辅助请求具有正确标识；使用已核验的网关字段。 |
| M2 | 路由与用量查看 | 能区分请求模型、实际成员、尝试过程及统计来源。 |
| M3 | 额度辅助选型 | 能力与硬约束满足后参考资源状态；先提供建议，再单独决定是否自动参与选型。 |

推荐先批准 M0；M1 可独立推进已具备依据的部分。M2、M3 作为独立后续阶段，不随 M0 自动实施。

## 3. 功能需求与验收场景

### MAG-01：按网关身份和接口能力启用

新增能力应只在当前网关已识别为 Magpie 时工作，并按接口实际结果判断可用范围。身份未知、凭据变化和接口无权限应具有不同状态。

**验收场景：**普通网关不发 Magpie 专用查询；同一作用域的另一个实例完成识别后能够共用结果；接口返回 403 时不将整个网关认定为非 Magpie。

### MAG-02：快捷状态展示

底部仅展示同一网关和凭据作用域的 OpenAI 最高已知剩余比例；先取单账户共同限制窗口的最低剩余值，再取可用 OpenAI 账户的最大值，不求和或平均。无有效读数时隐藏底部额度项，不显示未知或失败占位；有效旧读数保留旧标记，其他厂商、余额及具体失败原因在详情中保留。切换会话或模型不清空已有读数；会话状态模型名留在详情，且不单独证明实际成员。

**验收场景：**已用 20% 的有效窗口显示剩余 80%；同账户窗口剩余 90% 和 20% 时该账户按 20% 计算，另一个 OpenAI 账户剩余 60% 时摘要为 60%；其他厂商及余额不展开到底部，完整记录仍可在详情查看。另一个会话可复用并接收共享快照更新，不额外发起启动查询。没有有效 OpenAI 读数、首次读取失败或只有文本占位／无总量钱包时不显示额度项；有效 0% 仍须展示。无 UI 场景不启动独立界面服务。

### MAG-03：按厂商／产品族查看详细额度

支持逐层查看厂商／产品族、来源、账户、套餐和窗口；保留余额、重置时间、权益、错误及读数时间。分组不能损失源记录。

**验收场景：**同一账户经两个网关出现时可看见各自来源，不重复累计；不同套餐的剩余比例不相加；多厂商渠道身份不明时保留渠道分组；缺少窗口或读数的记录仍可见。

### MAG-04：读取与上游刷新分开

普通查看只读取已有数据；刷新供应商额度是明确的用户操作。允许刷新全部可见卡片，或明确说明影响范围的 provider／账户匹配组，不承诺协议无法表达的单卡定位。

**验收场景：**打开详情不调用刷新接口；空账户筛选影响该 provider 全部账户、同名多卡可能一起刷新时有明确说明；仅获单卡授权但无法唯一定位时不发请求；读数时间未变与失败保留均如实展示，刷新不消耗重置权益。

### MAG-05：按活动读取，空闲不轮询

读取应由明确活动触发并抑制重复请求。不得为额度功能建立空闲定时刷新、保活请求或自动开始待办。

**验收场景：**任务结束后只产生规则允许的一次读取；连续活动在缓存窗口内复用结果；空闲期间无查询；退出后不再发布该会话状态。

### MAG-06：准确表达请求归属

真实会话使用宿主 ID；辅助调用使用可区分的追踪身份。提供信息时必须区分 HTTP 请求头、顶层请求元数据、系统提示正文及本地会话文件。

**验收场景：**主会话和真实子会话不共用一个 ID；普通分支不被标为子代理；搜索、选型不会覆盖主任务的上下文统计；不会为改善标题自动改名。

### MAG-07：正确使用请求用途与父子关系

用途值应来自网关现有契约并与真实调用来源一致。字段解析能力、父会话归组规则、客户端专属行为分别验证。

**验收场景：**搜索和聊天选型仅在对应入口已支持时使用用途值，原生分类记录已确认的用途缺口；不发送自造的 `task`；不会仅因存在 `parent_thread_id` 就宣称任意辅助请求已形成父子关系；不能用修改 `User-Agent` 冒充其他客户端取得支持。

### MAG-08：查看实际路由及用量

区分请求模型、实际成员、响应正文模型名和网关统计；路由、请求统计及真实账单各有来源说明。

**验收场景：**别名经路由得到其他成员时保留两者；缺少响应头时不猜实际账户；接口受限时只影响对应视图；消费统计不被当成供应商账单或模型公开估价。

### MAG-09：额度作为选型参考

先确定任务能力、用户指定和固定审阅等硬约束，再判断额度是否能提供有效参考。账户级百分比不直接转换成统一厂商分数。

**验收场景：**低额度不会替换用户指定模型或降低正式设计审阅档位；未知、过期或不完整读数不被当作零余量；没有额度数据时仍遵守原选型逻辑；不为消耗临期额度自动发起任务。

## 4. 非功能需求

| ID | 要求 | 验收口径 |
| --- | --- | --- |
| MAG-N01 | 复用宿主认证和权限 | 不新增模型密钥文件、凭据优先级、认证客户端或用户配置迁移。 |
| MAG-N02 | 保持交互和推理连续 | 状态读取不阻塞任务完成；查询失败不使聊天失败；不新增付费自动重试或换模型。 |
| MAG-N03 | 作用域和数据生命周期一致 | 地址或凭据变化后不显示旧作用域数据；会话相关状态不被其他会话覆盖。 |
| MAG-N04 | 数据保真且来源明确 | 文本、未知、缺失、估算、共享余额和读数错误不被压成一个剩余比例。 |
| MAG-N05 | 保持现有兼容边界 | 不因本机宿主较新就提高最低版本；新增依赖或公共工具接口须单独评估。 |
| MAG-N06 | 区分验证层级 | 源码支持、隔离测试、真实接口、Pi UI 和 Pi Web 展示分别报告。 |

## 5. 非目标

- 不接管 Magpie 的账户路由、订阅登录、刷新调度或服务配置。
- 不修改 Magpie 服务端，不创造需要两端配合的新会话元数据协议。
- 不自动消费重置权益、充值、购买订阅、改预算或其他资源管理操作。
- 不新增跨设备通信、通用 HTTP 调试器或任意端点调用能力。
- 不复制历史消息，不为追踪改写消息、压缩策略或用户会话标题。
- 不将模型输入端点、模型目录、请求参数和额度可用性视为同一项能力。

## 6. 依赖与假设

1. 普通目录识别只作为简单启用条件，不提供服务真实性或接口完整性的保证。
2. 当前实例版本及部分接口权限尚未验收；相应能力具有局部不可用路径。
3. 标题、通用父子关系和元数据透传需要按既有源码核对，不假设只增加字段即可得到预期展示。
4. 初期以宿主现有命令、状态和选择界面承载功能，Pi Web 的具体呈现单独验收。
