## 3. M0：查询、快照和额度投影

### 3.1 预计修改范围

| 对象 | 允许的工作 |
| --- | --- |
| `extensions/magpie/`，拟新增 | 固定接口查询、作用域内存快照、额度分组和 UI；按职责和实际规模分文件，不新增仅聚合导出的 barrel。 |
| `extensions/provider/index.ts` | 注入已存在的网关身份、宿主服务、菜单和生命周期连接；保持装配职责。 |
| `extensions/provider/status.ts` 或新展示模块 | 保留现有目录状态，组合 Magpie 状态；不把额度失败覆盖成目录失败。 |
| 相邻 `.test.ts` 与宿主集成测试 | 使用合成配置与模拟 HTTP 验证真实实现。 |
| `package.json` 的测试命令 | 仅在新增测试入口确有需要时登记；不改版本、依赖或 peer 门槛。 |
| 根 `README.md` | 实现后更新必要使用入口；合并时保留现有修改，不在设计阶段编辑。 |

不写用户配置，不增加 `tsgw.json` 账户组或逐功能凭据，不新增持久额度文件。子路径引用继续遵守当前 imports 与 TypeScript 路径映射。

### 3.2 查询实现

1. 从当前 provider 的规范化根地址构造 B00 列明的固定接口，不接受任意 URL。
2. 通过宿主公开认证入口取得该作用域的有效地址、凭据与附加头，核对与当前识别作用域一致；按获准触发及宿主实际限制发请求，不自行读取旧凭据或建立解析优先级。
3. 只实现已批准阶段的接口；M0 不实现 route 长轮询、usage 扫描或权益消费。
4. 在接口入口解析对应结构：statusline、卡片和额度报告分别处理，不用一个“通用额度 JSON”类型替代。
5. 实现请求截止时间、调用者取消、错误摘要和单次操作；不扩展目录恢复重试策略。

### 3.3 快照与分组实现

- 网关级 cards 快照按现有地址／凭据作用域共享；会话级 statusline 另按真实会话 ID 区分。
- 将接口获取时间、逐记录读数时间和本次错误分开保存。新获取的旧读数不能刷新其读数时间。
- 作用域或生命周期改变后，不提交旧请求的 UI 结果；不让某一会话退出清掉其他仍使用的共享数据。
- 同一请求复用进行中的操作；已有成功结果按 B00 的 60 秒建议复用。失败不清空有效源数据。
- 分组保留完整源卡片；来源／账户／套餐／窗口不相同的数值不相加。重复关系不确定时保留并标注。
- 金额、积分、百分比、文本、无限额及未知状态分别投影；`text: true` 与占位零值不得形成“余量充足”。

完成判定：T01～T05 全部通过，原有目录和聊天行为不受查询失败影响。

## 4. M0：界面与触发

### 4.1 菜单建议

在现有 `/tsgw` 菜单中，仅识别为 Magpie 时增加：

1. **查看 Magpie 状态**：读取本会话 statusline，保留旧结果和获取状态。
2. **查看 Magpie 额度**：按需 GET cards，按厂商／产品族逐层展开。
3. **重新读取卡片**：绕过插件缓存 GET cards，不请求供应商刷新。
4. **刷新上游额度**：明确选择全部可见卡片或已说明的 provider／账户匹配范围，发一次对应 POST；不展示虚假的“仅此卡”承诺。

保留原有模型目录刷新与诊断。不新增模型可调用工具，不把显示标签固化为单元测试契约。无 UI 场景不借此新增输出文件或服务。

### 4.2 活动触发与共享状态

- 按用户确认的 Q2 修订，仅在使用匹配网关根地址的 `tsgw` 模型且正常用户任务最终完成的 `agent_settled` 异步 GET cards；60 秒抑制和快照在同一网关／凭据作用域共享，其他 provider 不触发，不挂到推理关键路径。显式会话状态仍读取带真实会话 ID 的 statusline。
- 压缩、辅助请求、自定义后台任务不因为“结束”就冒充一次用户任务完成；沿用并核对宿主生命周期事实。
- 请求 options 和 UI 发布只捕获必要的宿主服务／标识，不保留失效的会话上下文。
- 状态栏保留目录语义，仅附加 OpenAI 最高已知剩余比例：账户内取共同限制窗口的最小值，再取可用 OpenAI 账户最大值；无有效读数时隐藏额度项，有效旧值加旧标记，0% 仍展示；其他厂商、余额及详细源记录保留在菜单。摘要实现与定向回归位于 `extensions/magpie/summary.ts` 和 `summary.test.ts`。
- 切换会话或模型保留共享额度；界面订阅作用域目录及卡片更新，首次识别、重新识别和失效均通知界面，退出时取消订阅。控制器与服务回归覆盖跨会话复用、通知、作用域失效、读取失败和鉴权清除；“缓存获取失败”与“模型推理失败”分别表达。
- 不设置周期刷新；只有请求超时使用截止计时器。

### 4.3 显式上游刷新

筛选参数从当前源卡片取得，完整 provider 和账户值在 URL 编码，不从厂商分组标题反推。界面说明空 user 表示该 provider 全部账户，非空 user 按不区分大小写匹配，同名多卡可共同刷新；当前可见记录不保证覆盖全部受影响资源。用户只允许唯一单卡而协议不能表达时不发请求。不将 `{all:true}` 发成 Magpie 正文契约。

同目标刷新可共享在途结果；不同目标不建立自动队列。失败保留旧卡片；读数时间不变时如实提示，不因为 HTTP 200 自动给出“已取得最新额度”。不调用 `codex-reset` 等权益接口。

## 5. M1：请求输入补充

### 5.1 预计修改范围

- `extensions/provider/tracing.ts`：复用既有会话头与开关；在事实足够时补充普通会话的输入处理。
- `extensions/search/proxy.ts`：将独立辅助身份和已核准用途传入 options，组合现有 payload 处理。
- `extensions/delegation/chat-selection.ts`、`selection-race.ts`：按实际发起的选型请求传入必要追踪 options，维持选型顺序、预算和取消语义。
- `extensions/models/adapter/classifiers/adapter.ts`：仅在公开 options 未被完整消费时补齐必要传递，不复制协议解析。
- 相关隔离和宿主集成测试；没有接口依据的标题与通用父子上报不在修改清单中。

### 5.2 字段落地顺序

1. 确认已有 `X-Magpie-Session`、`AH-*` 在主任务、真实子会话、压缩和关闭追踪场景的行为。
2. 在独立搜索、聊天选型、原生分类中显式接入请求头；真实会话和辅助请求 ID 分开，不复用上一任务的 ID。
3. 对搜索和三路聊天选型按 B00 候选头核对接收、透传与展示。原生分类仅补身份；当前 `/v1/systemone` 不具备用途接收与记录路径，记录此已证实缺口，不安排付费探测替代源码结论。
4. 接收与传输验证通过后，仅对搜索启用 `web_search`、聊天选型启用 `routing`；已有用户元数据优先，不另写冲突副本。
5. 如果需要正文承载，先回写 B00 的方案变更，再在 `onPayload`／`before_provider_request` 最小改写顶层对象；保留既有模型操作和引用。

不得使用假客户端身份、Claude 专属 agent 头、新增父会话字段或消息历史改写来填补缺口。真实标题、父子关系方案不足时保持“未实现”，不以用途解析成功代替。

完成判定：T06～T08 通过，且按实际授权分别完成现场协议和界面验收；不将单协议结果外推到所有适配器。

## 6. M2：路由与用量

只有单独批准 M2 后才修改查询和菜单。

- 先实现会话最新 route 的一次 GET 和响应成员头读取；不启用 `after/wait` 常驻轮询。
- 再补 usage、usage/requests 和 limit 的受限查询，提供明确的时间范围／分页，默认不扫描历史全量。
- 输出保留请求模型、实际成员、状态、尝试顺序、时延、统计来源及权限缺口。
- 接口 JSON 的必需／可选字段及查询参数，须先从 B00 E1 固定源码及实际获准返回补成字段表，再实现解码。

完成判定：T09 通过；无权限、别名和并发会话最新状态的展示含义明确。

## 7. M3：额度辅助选型

只有单独批准 M3 后才讨论和修改选择器。

1. 补齐候选模型与实际额度池的映射依据、读数有效性及建议形式；先给出独立设计变更。
2. 优先实现非自动建议，确认是否有实际决策价值。
3. 若进一步批准自动参与，明确硬约束后的作用位置、有效性判定、缺失数据和失败处理；不得按百分比直接跨套餐评分。
4. 复核 delegation 的固定审阅、用户指定、档位和选型调用约束；不扩展付费请求次数。

完成判定：T10 通过；没有自动策略设计和明确授权时，只有建议展示，不修改 `policy.ts` 的实际选择行为。
