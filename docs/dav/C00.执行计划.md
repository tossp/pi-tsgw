# DAV 原生工具接入：执行草案

依据：[A00](A00.需求分析.md)、[B00](B00.规划设计.md)。用户已批准按“类型 → ID → 配置”推进统一配置与邮件适配。本机邮件迁移和源码发布已获独立授权；用户随后提供 DAV 账户并授权只读发现及继续接入。本批落实配置、optional 依赖和 10 个只读工具；不包含真实业务写入、发布安装或重载，实际进度见 [任务清单](000.TODO.md)。

## 配置草案

统一文件为 join(getAgentDir(), "tsgw.json")，权限 0600。顶层 imap、smtp、dav 分别映射账户 ID 到配置，允许 imap.tsn 与 dav.tsn 同名；每项不写 type，不增加 email 外层或 defaultSmtp。模型、provider 及宿主认证保留原入口，不迁移 settings.json.tsgw。

以下均为虚构占位值。DAV 条目字段为 url、user、password 与可选 timeZone；仅在显式业务调用中读取和校验，不读取旧 DAV 凭据。SMTP 默认使用该组对象枚举顺序中的首项，不受网络连接成功先后影响；显式指定账户优先，失败不换其他账户。

~~~json
{
  "imap": {
    "tsn": {
      "host": "imap.example.invalid",
      "port": 993,
      "tls": "implicit",
      "user": "<IMAP 登录账号>",
      "password": "<IMAP 应用密码>",
      "trashMailbox": "Trash",
      "junkMailbox": "Junk"
    }
  },
  "smtp": {
    "tsnet": {
      "host": "smtp.example.invalid",
      "port": 587,
      "tls": "starttls",
      "user": "<SMTP 登录账号>",
      "password": "<SMTP 应用密码>",
      "fromAddress": "sender@example.invalid"
    }
  },
  "dav": {
    "tsn": {
      "url": "https://dav.example.invalid/",
      "user": "<DAV 登录账号>",
      "password": "<DAV 应用密码>",
      "timeZone": "Asia/Shanghai"
    }
  }
}
~~~

统一入口读取文件并校验根对象，按泛型映射选择对应类型的工厂，工厂仅校验本组条目一次。缺文件、缺组或空组不影响工具声明注册，业务调用返回所需类型与本地配置指导；类型字段错误、未知 ID、文件错误和连接失败分别报告。某类型错误不影响其他有效类型；JSON 损坏或权限错误则按整体文件错误处理。密码原样保留，错误不包含字段值，不增加 enabled、凭据引用、环境变量覆盖或旧入口搜索层。

### 配置归并的实施边界

1. 先列清邮件独立入口等自定义功能的代码与文档读取点；模型 provider 的 settings.json.tsgw 保持原样，宿主核心配置、模型、OAuth、MCP 凭据均不在归并范围。
2. 代码改动实施前明确统一入口、分区字段、旧入口退出方式及验证清单。不自动增加新旧配置双读、优先级或启动时迁移器。
3. 用户配置实际迁移须另获授权并确认源、目标和字段清单；遇到目标已有配置须保留，不覆盖、不合并猜测、不删除旧文件或宿主字段。
4. 修改代码和文档不等于本机配置已迁移；实际迁移、重载与验收分开报告。

### 统一配置的首批实施清单

本批实施统一配置与邮件适配，不引入 davkit、不修改独立库、不实现 DAV 工具或读取 DAV 凭据。代码实施已获确认，后续邮件迁移按独立授权实施；实际结果见任务清单。

#### 字段归并

旧邮件配置的 imap、smtp 原样保留在统一文件顶层，字段语义、账户 ID 与值不变；defaultSmtp 从文件结构移除，改由 smtp 组首项决定默认。实际迁移须通过 accounts.defaultSmtp 核对旧默认身份，不能只看 JSON 文本顺序；纯数字 ID 按对象枚举规则排序，无法靠重排恢复旧默认时应明确显式指定 SMTP，不能默默改变发信身份。

| 原位置 | 新位置 | 保持内容 |
| --- | --- | --- |
| imap | imap | 原账户 ID；每项 host、port、tls、user、password、trashMailbox、junkMailbox。 |
| smtp | smtp | 原账户 ID；每项 host、port、tls、user、password、fromAddress，以及已配置的 fromName、allowSenderOverride、allowedFromDomains、envelopeFrom。 |
| defaultSmtp | 不保留 | 默认改取 smtp 组首项；显式指定出口优先，无 SMTP 时调用返回配置指导。 |

注册阶段不读取配置；第一次调用所需协议时加载并校验其组，无配置可在用户补齐后再次调用。成功加载的邮件类型按现有会话生命周期复用，已配置账户的修改通过重载生效，不加监听器或自动重连。IMAP 与 SMTP 不要求同时存在；SMTP 请求显式引用邮件线程时才需要对应 IMAP 配置。accounts 可列出已配置类型和安全的配置问题，不回显连接地址或认证信息。

复用现有协议类和校验工厂实现映射，不增加空壳配置类或通用配置框架。DAV 留待后续接入，本批不因存在 dav 就调用其客户端或校验其字段。

#### 退出旧入口与操作顺序

- 新代码只读 tsgw.json，不双读 tsgw-email.json，不建立优先级、不启动时迁移，也不删除旧文件。
- 只有旧文件时，新代码仍注册邮件工具，但调用报告缺配置；不把代码完成当作已完成现有邮箱切换。
- 个人配置迁移另获授权后，核对目标现状，保留旧 imap/smtp 条目与目标其他组，明确默认 SMTP 顺序并移除旧默认字段，要求 0600。目标已有同类型同 ID 时先确认，不直接覆盖；旧文件和宿主设置/认证保持原样。
- 不输出旧对象、密码、用户名、真实端点或整个目标文件。仅报告字段结构、校验结果和权限；本批不迁入 DAV 账户。
- 顺序为代码离线验收、获准迁移个人配置、另行发布/安装/重载与运行验收。未发布或未重载时不宣称当前会话已使用新入口。

## DAV 账户输出

accounts 工具仅返回 dav 组内 ID 和已配置的日历时区，不返回 URL、用户名或密码；日历／地址簿是否可用由 collections 指定 kind 后实际发现，不根据账户名猜测。collections 的实际集合地址是后续资源定位所需数据，不把它当成认证配置输出。

## 工具清单草案

工具统一 tsgw_dav_ 前缀，namespace=tsgw_dav，不冒用旧 MCP 的 tsn 前缀。本批只实现 accounts、collections、四组 list/get，共 10 个；下表中的 contact_search 与全部写入仍是后续规划，不注册空壳工具。

| 分组 | 建议后缀 | 性质 | 主要输入 |
| --- | --- | --- | --- |
| 公共 | accounts | 只读、本地 | 无 |
| 公共 | collections | 只读、联网 | kind、account |
| 日程 | event_list、event_get | 只读 | 账户/集合/时间范围，或 resourceUrl |
| 日程 | event_create、event_update、event_delete | 写入 | 明确集合或资源、字段、更新/删除所需版本与组件身份 |
| 联系人 | contact_list、contact_search、contact_get | 只读 | 账户/地址簿/搜索词，或 resourceUrl |
| 联系人 | contact_create、contact_update、contact_delete | 写入 | 明确集合或资源、字段、更新/删除所需版本 |
| 待办 | todo_list、todo_get | 只读 | 账户/集合/过滤条件，或 resourceUrl |
| 待办 | todo_create、todo_update、todo_delete | 写入 | 明确集合或资源、字段、更新/删除所需版本与组件身份 |
| 日记 | journal_list、journal_get | 只读 | 账户/集合/过滤条件，或 resourceUrl |
| 日记 | journal_create、journal_update、journal_delete | 写入 | 明确集合或资源、字段、更新/删除所需版本与组件身份 |

预计最多 23 个工具；兼容宿主上声明不随配置有无变化，调用时再检查所需账户、协议能力和运行环境。常用业务字段继续结构化，不把用户任务改成手填完整 ICS/VCF。高级完整逻辑属性与提醒的覆盖语义须在 schema 中分别明确：省略保留；properties: [] 不修改；removeProperties 显式删除命名属性；alarms: [] 清空提醒；null 仅用于明确支持删除的标量，不推广到通用属性；不得混用。

### 旧工具对照与 API 差异

只读盘点确认旧实现有 25 个工具。新命名空间不是旧 MCP schema 的别名；建议去掉两个显式连接入口，将独立的重复事件创建合入 event_create 的可选 rrule，再把 calendar_list 扩为 collections 并增加 accounts，合计 23 个。旧 MCP 不在本轮删除，命名和参数变化不会改动它的调用者。

| 旧工具 | 新工具后缀 | davkit 公开 API 或编排 |
| --- | --- | --- |
| dav_connect、dav_reconnect | 不保留 | 配置驱动的按调用初始化，不暴露密码参数 |
| calendar_list | collections；另增 accounts | discover(kind)；accounts 仅列出本地可用 ID |
| calendar_event_list | event_list | query(component=VEVENT) 后逐资源 expandEvents |
| calendar_event_get | event_get | GET 实际 resourceUrl、parseCalendar、按 UID/例外选择 |
| calendar_event_create、calendar_event_recurring_create | event_create，可选 rrule | buildCalendarComponent(VEVENT)、create |
| calendar_event_update | event_update | GET、updateCalendarComponent、update；旧便捷时间编辑存在下述缺口 |
| calendar_event_delete | event_delete | 整资源身份保护后 delete；保护能力存在下述缺口 |
| contacts_list、contacts_get | contact_list、contact_get | query 或 GET、parseContact |
| contacts_search | contact_search | 全集合 query 后本地多字段投影，不用 FN 查询冒充 |
| contacts_create | contact_create | buildContact、create |
| contacts_update | contact_update | GET、updateContact、update；旧首值便捷编辑存在下述缺口 |
| contacts_delete | contact_delete | GET 确认身份和强 ETag 后 delete |
| calendar_todo_list/get/create/update/delete | todo_list/get/create/update/delete | VTODO 查询、parseCalendar、build/updateCalendarComponent、条件写入/删除 |
| calendar_journal_list/get/create/update/delete | journal_list/get/create/update/delete | VJOURNAL 查询、parseCalendar、build/updateCalendarComponent、条件写入/删除 |

事实入口为独立仓库 dav-mcp 的 internal/tools/calendar*.go、contacts*.go、todo*.go、journal*.go；新库 API 位于 davkit 的 src/dav/index.ts、src/ical/component.ts、model.ts、expand.ts 和 src/vcard/index.ts。

| 差异 | 草案处理 |
| --- | --- |
| 账户/集合省略会隐式选择或跨账户聚合 | 新工具显式选择，不复制旧“第一个集合”默认；跨集合由调用方明确逐个请求。 |
| 库与旧工具均无分页、limit/cursor | 首版不新增这些参数；返回摘要和完整性标识，输出过大明确失败或要求缩小范围，不静默截断冒充完整结果。 |
| 旧搜索覆盖 FN/N/NICKNAME/TITLE/ROLE/ORG/NOTE/EMAIL/TEL，并规范化电话 | 当前 N/NICKNAME/ORG 等仅提供 rawValue，不能以 value ?? rawValue 当作旧解码值。保留旧语义前须闭合解码投影；库 text 过滤仅覆盖 FN，不能用来缩小候选。 |
| UID 与存储路径不同 | 列表返回实际 resourceUrl；GET/修改/删除使用此 URL，不重建 uid.ics/vcf 路径；组件选择仍带 UID。 |
| 主件、已有例外、展开实例不同 | 使用完整 RECURRENCE-ID 逻辑行选择已有例外，拒绝歧义/RANGE；不创建新例外、不删除单次合成实例。 |
| 旧日历更新维护修订，库不自动维护 | 建议插件在实际变更时通过公开属性编辑维护 DTSTAMP、LAST-MODIFIED、SEQUENCE；新建补 LAST-MODIFIED，不改变 UID/RECURRENCE-ID。无改动不刷新。 |
| 旧联系人创建/修改维护 REV，库不自动维护 | 建议插件显式维护 REV，并在工具入口保留旧禁止用户直接编辑 REV 的契约；不自行切割原文。 |
| 旧 contacts_get 的属性原文列表与新结构模型不同 | 新工具明确返回结构化属性；raw=true 才返回 GET 原文，不宣称文本输出逐字兼容。 |
| Map 与 JSON 不等价 | 联系人 parameters Map 显式转普通对象；日历公开模型已是普通对象，不重复转换或漏字段。 |

### 独立库的小接口缺口

以下是接入旧业务语义所需的能力，不是已存在的导出，也不是协议重写：

1. 保持旧时间表示及非目标参数的 start/end/due/date 标量编辑。现有通用属性组替换可以显式替换整项，但不能直接冒充旧保留式标量接口。
2. 联系人 email/phone/org/note 的首值编辑，保留其余值及原参数。现有 updateContact.properties 是整组替换，不能用单行覆盖冒充首值更新。
3. 整资源删除身份校验。旧 ValidateDeleteResource 拒绝其他类型或其他 UID，允许同系列主件/例外及共享时区；parseCalendar 只投影已知组件，不等于该校验，未知嵌套内容不能被忽略。

另有搜索投影差异：N/NICKNAME/ORG 等结构或列表值中的转义尚未解码，直接匹配 rawValue 会漏掉“测试,甲”对 ORG:测试\,甲;研发部 这类查询。保留旧搜索前需闭合必要的解码投影；具体复用或补足方式在独立库任务中确定，不预先强制新增一套 API，也不在插件复制解析层。依据为 davkit/src/vcard/properties.ts 的 structuredOrList 与 projectProperty。

建议先由 davkit 增补必要的公开能力和保留回归，再让插件消费经发布的版本。相关实现与发版属于独立仓库任务，须另获授权，本轮不修改。若选择首版仅暴露新库原生通用编辑、暂不开放不安全删除，也须明确缩小工具契约，不把能力差异当作已完成。

修订元数据属于应用业务策略，可通过现有公开属性编辑编排，不要求为此复制内容编辑器或再加第四套解析 API。旧依据：internal/ical/update.go:147-169、builder.go:49-64；internal/vcard/builder.go:41-42、update.go:123-136。

## 实施批次与检查标准

### 前置：确认编辑兼容契约

先确认保留旧便捷标量编辑与安全删除，还是明确缩小到新库原生能力。按本草案建议，独立 davkit 任务先闭合上述三个公开接口缺口及搜索解码投影差异，再更新插件依赖目标；不得在插件中复制内部 parser、偏移编辑或递归组件扫描来绕过边界。当前用户已授权只读工具先行；联系人搜索仍因解码投影缺口而不注册，不能据此认定完整工具已接入。

### 批次一：配置、兼容与只读工具

本批依据：用户已明确配置 dav 账户并授权只读发现及继续接入；采用 davkit@0.1.0 optionalDependencies，保持全插件 Pi 1.2+ 基线，仅 DAV 业务调用要求 Node.js 24。实现 url/user/password 与可选 timeZone 的配置工厂；不改用户配置，不读取旧凭据。写入兼容契约与联系人多字段搜索留待独立库缺口闭合，不在本批补库。

- 工具声明在兼容宿主上始终可发现；调用时缺 dav 组、配置无效或环境不满足才报对应原因，不提前加载 davkit。统一文件损坏或权限不符按整体配置错误处理，不为此增加恢复解析器。
- 首批注册 accounts、collections、四组 list/get 共 10 个工具，不注册联系人 search 或写入；实际网络只发生于具备有效账户的业务调用。accounts 本地元数据不要求加载 davkit，业务读取才校验 Node.js 与可选库。
- 在全新的调用范围创建客户端；将调用 signal、会话信号与 fetch 入参 signal 合并，不在共享对象上临时更换 signal。会话结束取消进行中的读取。DAV 配置按次加载，不增加缓存或监听器。
- 根 URL 的发现按 kind 选择标准 well-known 入口；仅发现可跟随最多三次同源跳转，并由库按新入口重建发现基准。明确路径不改写，GET/REPORT 不跟随跳转；认证失败或其他 HTTP 错误不重试，不尝试其他端口。
- 按明确集合查询，区分资源和组件身份，详情按需 GET；列表若无法完整处理须明确失败，不能静默跳过错误。工具结果上限为 256 KiB，超限报 RESULT_TOO_LARGE，不输出截断列表；首版无分页。事件时间窗口支持秒精度基本 UTC 或带 Z／偏移的 ISO 8601，非零毫秒明确拒绝，不舍入。
- 事件 REPORT 只按 VEVENT 筛选，不附服务端时间窗口；读取所选日历全部事件资源后，用现有 expandEvents 按明确时区和窗口解释，避免服务端 floating 时区不同造成漏项。不自行补时区协议或重复算法；代价是传输量与本地处理量增大，大日历仍可能触发库预算或超时并明确失败。以服务端 UTC、调用 Asia/Shanghai 的合成回归验证不漏项，同时排除窗口外资源。
- 验证 Node.js 22 的普通和 engine-strict 安装，Node.js 24 的完整及 omit=optional 安装；不以修改模拟版本字符串替代安装验收。

### 批次二：创建、修改与删除

- 四类创建均通过库 API 生成资源，随机文件名配合 If-None-Match；不允许调用方任意更换 UID 或 VERSION。事件创建以可选 rrule 支持重复系列，明确时区，不将本地重复固定转成 UTC 后改变当地时间语义。
- 首值和保留式时间编辑使用已验收的独立库入口；修订元数据按上述应用策略编排。日记 date 要求显式提供，避免沿用旧 UTC 当日默认与账户时区混淆。
- 更新传入上次读取的强 ETag，GET 后比较版本、选择组件，借库作保留式编辑，条件写回；若没有改动，不发 PUT。
- 冲突或无法精确选择时停止，不做扩大查询、自动选择目标、重新生成身份或无条件覆盖。
- 删除只针对明确整资源及其强 ETag，不能用 occurrence 的身份暗示只删单次。多组件/混合类型资源的范围必须显式核验。
- 只读、创建和破坏性工具分别填写 annotations；授权仍由宿主与本次用户请求决定。
- 成功、失败、冲突和远端结果未确认分别输出，不自动重试；仅在写入尚无确定结果时报告未知，不把已确认成功因后续清理、取消或回读失败降为未知。普通输出不带源正文或协议异常。

新增测试接入仓库已有 Node 测试入口，不引入另一套测试框架。定向范围：

1. 隔离 agent-dir；统一文件、分区缺省、无效 JSON、权限、账户映射、URL/时区及安全消息；有效分区不因其他分区字段错误而停用，宿主核心配置与认证不变。
2. 模拟宿主：deferred 始终注册、调用时配置指导、outputSchema 与 structuredContent、版本门和其他能力不受影响。
3. 本地 HTTP：发现、查询、GET、四类 CRUD、条件冲突、GET 源文本/版本与 REPORT 区别、取消和结果未确认。
4. 合成内容：联系人字段与参数保留、事件/待办/日记分型、已有重复例外选择、相对提醒依赖、跨时区和重复预算。
5. 修改路径主动 LSP 检查；包清单不含设计文档、测试、真实配置或数据；技能描述不声称功能已经生产验收。

只补验证插件编排的新行为与实际回归风险，不复制核心库全部测试或为数量重复做规则测试。

### 批次四：外部验收和切换

这一批逐项另行授权，不随实施代码审批自动执行：

1. 用户显式提供/配置账户后，真实只读验收发现、集合、资源、UID 和 ETag；记录范围与计数，不展示无关正文。
2. 授权明确集合和虚构对象清单后，验证创建、修改、冲突及删除，按实际结果报告；不自动补偿清理。
3. 另行发布插件、更新本机并重载；npm 成功不等于会话已加载。
4. 确认新入口已验收后，用户再决定旧 MCP 停用，不自动删除服务、凭据或旧配置。

未验收前保留旧 MCP，不把新旧工具并用作自动写入回退。无配置或环境不兼容时返回明确配置/环境错误，不隐式切换到旧 MCP。
