依据：[A00](A00.需求分析.md)、[B00](B00.规划设计.md)。既有配置、只读工具、搜索与写入批次保留为接入依据；当前新增执行范围见[策略修订](#策略修订读时保真写时合规)。设计和两仓库本地实施已获批准，独立库 0.3.0 已另获授权发布并验收；当前在插件锁定该版本，实施读取保真与最终写前门控。插件实施只含源码与离线验证，不包含插件提交、发布安装、重载、个人配置变更或真实数据写入；实际进度见 [任务清单](000.TODO.md)。

## 配置草案

统一文件为 join(getAgentDir(), "tsgw.json")，权限 0600。顶层 imap、smtp、dav 分别映射账户 ID 到配置，允许 imap.tsn 与 dav.tsn 同名；每项不写 type，不增加 email 外层或 defaultSmtp。模型、provider 及宿主认证保留原入口，不迁移 settings.json.tsgw。

以下均为虚构占位值。DAV 条目字段为 url、user、password 与可选 timeZone；仅在显式业务调用中读取和校验，不读取旧 DAV 凭据。SMTP 默认使用该组对象枚举顺序中的首项，不受网络连接成功先后影响；显式指定账户优先，失败不换其他账户。

~~~json
{
  "imap": {
    "tsn": {
      "host": "imap.example.invalid",
      "port": 993,
      "tls": "implicit",
      "user": "<IMAP 登录账号>",
      "password": "<IMAP 应用密码>",
      "trashMailbox": "Trash",
      "junkMailbox": "Junk"
    }
  },
  "smtp": {
    "tsnet": {
      "host": "smtp.example.invalid",
      "port": 587,
      "tls": "starttls",
      "user": "<SMTP 登录账号>",
      "password": "<SMTP 应用密码>",
      "fromAddress": "sender@example.invalid"
    }
  },
  "dav": {
    "tsn": {
      "url": "https://dav.example.invalid/",
      "user": "<DAV 登录账号>",
      "password": "<DAV 应用密码>",
      "timeZone": "Asia/Shanghai"
    }
  }
}
~~~

统一入口读取文件并校验根对象，按泛型映射选择对应类型的工厂，工厂仅校验本组条目一次。缺文件、缺组或空组不影响工具声明注册，业务调用返回所需类型与本地配置指导；类型字段错误、未知 ID、文件错误和连接失败分别报告。某类型错误不影响其他有效类型；JSON 损坏或权限错误则按整体文件错误处理。密码原样保留，错误不包含字段值，不增加 enabled、凭据引用、环境变量覆盖或旧入口搜索层。

### 配置归并的实施边界

1. 先列清邮件独立入口等自定义功能的代码与文档读取点；模型 provider 的 settings.json.tsgw 保持原样，宿主核心配置、模型、OAuth、MCP 凭据均不在归并范围。
2. 代码改动实施前明确统一入口、分区字段、旧入口退出方式及验证清单。不自动增加新旧配置双读、优先级或启动时迁移器。
3. 用户配置实际迁移须另获授权并确认源、目标和字段清单；遇到目标已有配置须保留，不覆盖、不合并猜测、不删除旧文件或宿主字段。
4. 修改代码和文档不等于本机配置已迁移；实际迁移、重载与验收分开报告。

### 统一配置的首批实施清单

本批实施统一配置与邮件适配，不引入 davkit、不修改独立库、不实现 DAV 工具或读取 DAV 凭据。代码实施已获确认，后续邮件迁移按独立授权实施；实际结果见任务清单。

#### 字段归并

旧邮件配置的 imap、smtp 原样保留在统一文件顶层，字段语义、账户 ID 与值不变；defaultSmtp 从文件结构移除，改由 smtp 组首项决定默认。实际迁移须通过 accounts.defaultSmtp 核对旧默认身份，不能只看 JSON 文本顺序；纯数字 ID 按对象枚举规则排序，无法靠重排恢复旧默认时应明确显式指定 SMTP，不能默默改变发信身份。

| 原位置 | 新位置 | 保持内容 |
| --- | --- | --- |
| imap | imap | 原账户 ID；每项 host、port、tls、user、password、trashMailbox、junkMailbox。 |
| smtp | smtp | 原账户 ID；每项 host、port、tls、user、password、fromAddress，以及已配置的 fromName、allowSenderOverride、allowedFromDomains、envelopeFrom。 |
| defaultSmtp | 不保留 | 默认改取 smtp 组首项；显式指定出口优先，无 SMTP 时调用返回配置指导。 |

注册阶段不读取配置；第一次调用所需协议时加载并校验其组，无配置可在用户补齐后再次调用。成功加载的邮件类型按现有会话生命周期复用，已配置账户的修改通过重载生效，不加监听器或自动重连。IMAP 与 SMTP 不要求同时存在；SMTP 请求显式引用邮件线程时才需要对应 IMAP 配置。accounts 可列出已配置类型和安全的配置问题，不回显连接地址或认证信息。

复用现有协议类和校验工厂实现映射，不增加空壳配置类或通用配置框架。DAV 留待后续接入，本批不因存在 dav 就调用其客户端或校验其字段。

#### 退出旧入口与操作顺序

- 新代码只读 tsgw.json，不双读 tsgw-email.json，不建立优先级、不启动时迁移，也不删除旧文件。
- 只有旧文件时，新代码仍注册邮件工具，但调用报告缺配置；不把代码完成当作已完成现有邮箱切换。
- 个人配置迁移另获授权后，核对目标现状，保留旧 imap/smtp 条目与目标其他组，明确默认 SMTP 顺序并移除旧默认字段，要求 0600。目标已有同类型同 ID 时先确认，不直接覆盖；旧文件和宿主设置/认证保持原样。
- 不输出旧对象、密码、用户名、真实端点或整个目标文件。仅报告字段结构、校验结果和权限；本批不迁入 DAV 账户。
- 顺序为代码离线验收、获准迁移个人配置、另行发布/安装/重载与运行验收。未发布或未重载时不宣称当前会话已使用新入口。

## DAV 账户输出

accounts 工具仅返回 dav 组内 ID 和已配置的日历时区，不返回 URL、用户名或密码；日历／地址簿是否可用由 collections 指定 kind 后实际发现，不根据账户名猜测。collections 的实际集合地址是后续资源定位所需数据，不把它当成认证配置输出。

## 工具清单草案

工具统一 tsgw_dav_ 前缀，namespace=tsgw_dav，不冒用旧 MCP 的 tsn 前缀。首批 accounts、collections、四组 list/get 共 10 个已实现；本批补齐 contact_search 与四类 create/update/delete 共 13 个，不注册空壳工具。

| 分组 | 建议后缀 | 性质 | 主要输入 |
| --- | --- | --- | --- |
| 公共 | accounts | 只读、本地 | 无 |
| 公共 | collections | 只读、联网 | kind、account |
| 日程 | event_list、event_get | 只读 | 账户/集合/时间范围，或 resourceUrl |
| 日程 | event_create、event_update、event_delete | 写入 | 明确集合或资源、字段、更新/删除所需版本与组件身份 |
| 联系人 | contact_list、contact_search、contact_get | 只读 | 账户/地址簿/搜索词，或 resourceUrl |
| 联系人 | contact_create、contact_update、contact_delete | 写入 | 明确集合或资源、字段、更新/删除所需版本 |
| 待办 | todo_list、todo_get | 只读 | 账户/集合/过滤条件，或 resourceUrl |
| 待办 | todo_create、todo_update、todo_delete | 写入 | 明确集合或资源、字段、更新/删除所需版本与组件身份 |
| 日记 | journal_list、journal_get | 只读 | 账户/集合/过滤条件，或 resourceUrl |
| 日记 | journal_create、journal_update、journal_delete | 写入 | 明确集合或资源、字段、更新/删除所需版本与组件身份 |

完整范围为 23 个工具；兼容宿主上声明不随配置有无变化，调用时再检查所需账户、协议能力和运行环境。常用业务字段继续结构化，不把用户任务改成手填完整 ICS/VCF。高级完整逻辑属性与提醒的覆盖语义须在 schema 中分别明确：省略保留；properties: [] 不修改；removeProperties 显式删除命名属性；alarms: [] 清空提醒；null 仅用于明确支持删除的标量，不推广到通用属性；不得混用。

### 旧工具对照与 API 差异

只读盘点确认旧实现有 25 个工具。新命名空间不是旧 MCP schema 的别名；建议去掉两个显式连接入口，将独立的重复事件创建合入 event_create 的可选 rrule，再把 calendar_list 扩为 collections 并增加 accounts，合计 23 个。旧 MCP 不在本轮删除，命名和参数变化不会改动它的调用者。

| 旧工具 | 新工具后缀 | davkit 公开 API 或编排 |
| --- | --- | --- |
| dav_connect、dav_reconnect | 不保留 | 配置驱动的按调用初始化，不暴露密码参数 |
| calendar_list | collections；另增 accounts | discover(kind)；accounts 仅列出本地可用 ID |
| calendar_event_list | event_list | query(component=VEVENT) 后逐资源 expandEvents |
| calendar_event_get | event_get | GET 实际 resourceUrl、parseCalendar、按 UID/例外选择 |
| calendar_event_create、calendar_event_recurring_create | event_create，可选 rrule | buildCalendarComponent(VEVENT)、create |
| calendar_event_update | event_update | GET、0.2.0 保留式时间编辑与 updateCalendarComponent、条件 update |
| calendar_event_delete | event_delete | GET、assertCalendarResourceIdentity 整资源保护后条件 delete |
| contacts_list、contacts_get | contact_list、contact_get | query 或 GET、parseContact |
| contacts_search | contact_search | 全集合 query 后本地多字段投影，不用 FN 查询冒充 |
| contacts_create | contact_create | buildContact、create |
| contacts_update | contact_update | GET、0.2.0 firstProperties 首值编辑与 updateContact、条件 update |
| contacts_delete | contact_delete | GET 确认身份和强 ETag 后 delete |
| calendar_todo_list/get/create/update/delete | todo_list/get/create/update/delete | VTODO 查询、parseCalendar、build/updateCalendarComponent、条件写入/删除 |
| calendar_journal_list/get/create/update/delete | journal_list/get/create/update/delete | VJOURNAL 查询、parseCalendar、build/updateCalendarComponent、条件写入/删除 |

事实入口为独立仓库 dav-mcp 的 internal/tools/calendar*.go、contacts*.go、todo*.go、journal*.go；新库 API 位于 davkit 的 src/dav/index.ts、src/ical/component.ts、model.ts、expand.ts 和 src/vcard/index.ts。

| 差异 | 草案处理 |
| --- | --- |
| 账户/集合省略会隐式选择或跨账户聚合 | 新工具显式选择，不复制旧“第一个集合”默认；跨集合由调用方明确逐个请求。 |
| 库与旧工具均无分页、limit/cursor | 首版不新增这些参数；返回摘要和完整性标识，输出过大明确失败或要求缩小范围，不静默截断冒充完整结果。 |
| 旧搜索覆盖 FN/N/NICKNAME/TITLE/ROLE/ORG/NOTE/EMAIL/TEL，并规范化电话 | 0.2.0 的 components/items 提供结构化解码，搜索遍历叶值或标量 value，不以 rawValue 冒充解码；库 text 过滤仅覆盖 FN，不能用来缩小候选。 |
| UID 与存储路径不同 | 列表返回实际 resourceUrl；GET/修改/删除使用此 URL，不重建 uid.ics/vcf 路径；组件选择仍带 UID。 |
| 主件、已有例外、展开实例不同 | 使用完整 RECURRENCE-ID 逻辑行选择已有例外，拒绝歧义/RANGE；不创建新例外、不删除单次合成实例。 |
| 旧日历更新维护修订，库不自动维护 | 建议插件在实际变更时通过公开属性编辑维护 DTSTAMP、LAST-MODIFIED、SEQUENCE；新建补 LAST-MODIFIED，不改变 UID/RECURRENCE-ID。无改动不刷新。 |
| 旧联系人创建/修改维护 REV，库不自动维护 | 建议插件显式维护 REV，并在工具入口保留旧禁止用户直接编辑 REV 的契约；不自行切割原文。 |
| 旧 contacts_get 的属性原文列表与新结构模型不同 | 新工具明确返回结构化属性；raw=true 才返回 GET 原文，不宣称文本输出逐字兼容。 |
| Map 与 JSON 不等价 | 联系人 parameters Map 显式转普通对象；日历公开模型已是普通对象，不重复转换或漏字段。 |

### 独立库的小接口缺口

以下四项前置能力已由独立 davkit@0.2.0 提供，实际发布包及插件接入所需定向探针已通过，不再作为未闭合缺口：

1. updateCalendarComponent 的 start/end/due 保留式标量编辑；插件将日记 date 映射到 start，不复制时间或原文编辑算法。
2. updateContact.firstProperties 的 email/tel/org/note 首值编辑；插件 phone 映射 tel，ORG 使用明确组件数组。源首项显式 VALUE=uri 时沿用旧工具的业务限制：phone 标量不改写其 URI 值，要求完整 properties；null 仅删除首项。普通电话不因此被要求输入 URI。properties 仍按同名属性整组替换，不改变原有语义。
3. assertCalendarResourceIdentity 检查完整组件树，保护整资源删除；不使用 parseCalendar 的已知组件投影替代此守卫。
4. 联系人 components/items 解码投影保留结构边界；N/ADR/ORG 及 NICKNAME/CATEGORIES 的转义分隔符和空项经验证，旧编码不提供伪造解码。

本批只消费发布版本，不修改独立库。若实际接入发现确认缺陷，向 tossp/davkit 提 issue，附最小复现与验收口径，不在插件复制核心解析或编辑逻辑绕过。

修订元数据属于应用业务策略，可通过现有公开属性编辑编排，不要求为此复制内容编辑器或再加第四套解析 API。旧依据：internal/ical/update.go:147-169、builder.go:49-64；internal/vcard/builder.go:41-42、update.go:123-136。

## 实施批次与检查标准

### 前置：确认编辑兼容契约

已确认保留便捷标量编辑、安全删除及多字段搜索；独立 davkit@0.2.0 的四项公开能力已核验满足要求，用户继续授权本批实现和离线验证。更新 optional 版本并消费公开入口，不复制内部 parser、偏移编辑或递归组件扫描；全部通过验证后才将完整工具接入标为完成。

### 批次一：配置、兼容与只读工具

本批依据：用户已明确配置 dav 账户并授权只读发现及继续接入；采用 davkit@0.1.0 optionalDependencies，保持全插件 Pi 1.2+ 基线，仅 DAV 业务调用要求 Node.js 24。实现 url/user/password 与可选 timeZone 的配置工厂；不改用户配置，不读取旧凭据。写入兼容契约与联系人多字段搜索留待独立库缺口闭合，不在本批补库。

- 工具声明在兼容宿主上始终可发现；调用时缺 dav 组、配置无效或环境不满足才报对应原因，不提前加载 davkit。统一文件损坏或权限不符按整体配置错误处理，不为此增加恢复解析器。
- 首批注册 accounts、collections、四组 list/get 共 10 个工具，不注册联系人 search 或写入；实际网络只发生于具备有效账户的业务调用。accounts 本地元数据不要求加载 davkit，业务读取才校验 Node.js 与可选库。
- 在全新的调用范围创建客户端；将调用 signal、会话信号与 fetch 入参 signal 合并，不在共享对象上临时更换 signal。会话结束取消进行中的读取。DAV 配置按次加载，不增加缓存或监听器。
- 根 URL 的发现按 kind 选择标准 well-known 入口；仅发现可跟随最多三次同源跳转，并由库按新入口重建发现基准。明确路径不改写，GET/REPORT 不跟随跳转；认证失败或其他 HTTP 错误不重试，不尝试其他端口。
- 按明确集合查询，区分资源和组件身份，详情按需 GET；原批次采用内容失败即整批失败；后续按本轮策略修订返回失败记录及原文、明确不完整，不能静默跳过错误。工具结果上限为 256 KiB，超限报 RESULT_TOO_LARGE，不输出截断列表；首版无分页。事件时间窗口支持秒精度基本 UTC 或带 Z／偏移的 ISO 8601，非零毫秒明确拒绝，不舍入。
- 事件 REPORT 只按 VEVENT 筛选，不附服务端时间窗口；读取所选日历全部事件资源后，用现有 expandEvents 按明确时区和窗口解释，避免服务端 floating 时区不同造成漏项。不自行补时区协议或重复算法；代价是传输量与本地处理量增大，大日历仍可能触发库预算或超时并明确失败。以服务端 UTC、调用 Asia/Shanghai 的合成回归验证不漏项，同时排除窗口外资源。
- 验证 Node.js 22 的普通和 engine-strict 安装，Node.js 24 的完整及 omit=optional 安装；不以修改模拟版本字符串替代安装验收。

本批还补齐 contact_search：明确地址簿后完整 REPORT，在本地遍历库的已解码字段匹配，不做 FN 预过滤，不把不可解码旧编码当作明文。

- 本批代码清单：package.json/lock 升级 optional davkit 至 0.2.0；新增日历写入、联系人搜索和写入及各自 schema/回归；共享 mutations.ts 负责旧版本核对和随机路径，client.ts 区分传输结果，tools.ts/schema.ts 完成声明和输出；同步宿主集成测试、技能、README、边界说明及本套正式文档。不得修改个人配置或 davkit 项目。
- 四类创建均通过库 API 生成资源，随机文件名配合 If-None-Match；不允许调用方任意更换 UID 或 VERSION。生成身份在请求前仅记录于本次调用，结果未知时附 account/uid 与日历 kind，支持按实际 URL 直接 GET，不依赖列表、展开或正文再解析。事件创建以可选 rrule 支持重复系列，明确时区，不将本地重复固定转成 UTC 后改变当地时间语义。

- 更新传入上次读取的强 ETag，GET 后比较版本、选择组件，借库作保留式编辑，条件写回；若没有改动，不发 PUT。
- 冲突或无法精确选择时停止，不做扩大查询、自动选择目标、重新生成身份或无条件覆盖。

- 只读、创建和破坏性工具分别填写 annotations；授权仍由宿主与本次用户请求决定。
- 成功、失败、冲突和远端结果未确认分别输出，不自动重试；仅在写入尚无确定结果时报告未知，不把已确认成功因后续清理、取消或回读失败降为未知。普通输出不带源正文或协议异常。

### 第一步：独立库的最小扩展

下列新增公开契约已由 davkit@0.3.0 实现、发布并完成实际消费者验收，0.2.0 不包含；插件本轮锁定 0.3.0 消费。具体检查与 unsupported 范围由库既有 A/B/C 及 000.TODO 承接；保持三个子路径，不新增运行时依赖或 Pi 概念。

- `davkit/ical` 增加 `validateCalendarResource(raw)`，`davkit/vcard` 增加 `validateContact(raw)`，同步导出对应结果类型。两者不访问网络、不改写/重新序列化输入、不需要查询窗口，也不展开无限重复序列。
- 返回 `{ valid, issues }`；每个问题提供稳定 `code`、类别 `invalid` 或 `unsupported`、组件树位置/属性名和固定安全说明。`valid: true` 仅在整份候选完成约定检查且无阻塞问题时返回；原始值、UID、正文和底层异常不进入诊断模板。按扩展语法允许保留的内容不因“未知”被判错误；无法安全验证的已知内容必须报 unsupported，不能默默当作已验证。
- 日历检查整份 VCALENDAR 的根属性与结构、全部业务主件/例外、已支持字段的值类型和关联、RRULE/RDATE/EXDATE、既有 VALARM 和 VTIMEZONE 子结构；复用现有时间、时长、属性、提醒与身份检查，不以只检查目标组件或整资源删除守卫替代。
- 联系人按实际 vCard 版本检查整张卡的结构、必需/单值约束、结构化文本及已支持的日期/URI 等值类型；至少拒绝已复现的无效 BDAY、REV 和显式 URI 电话。旧编码或扩展语义无法可靠判断时明确报告边界，不伪造解码或自动删字段。
- 随接口给出实际检查范围和 unsupported 清单及合成回归；不把“遍历所有组件”称为“实现全部 RFC”。不得通过排除本次已确认的错误类型，把它们从校验范围中消失。新入口与旧读/编辑入口分开，避免为写校验破坏 raw 读取。

结果契约：

1. 列表保留 `items` 的原含义，新增 `unresolvedResources`；每个失败资源含实际 resourceUrl、etag、raw、rawSource、失败阶段和安全诊断，可附已可靠解析的组件/属性。事件 items 仍只含已确定发生项；失败主件/例外不混入其中。
2. `resourcesComplete` 说明查询资源是否完整取得，既有 `complete` 说明请求的业务结果能否判定完整。资源内容失败时可 `ok: true, resourcesComplete: true, complete: false`，并附完整失败记录；传输、协议、取消或结果超限仍 `ok: false`，不返回伪完整片段。
3. UID/状态/搜索词/时间窗无法判定的资源保留为未知，不假定满足也不假定不满足。REPORT 仍只筛组件，不恢复服务端时间窗预过滤。组件身份和筛选能可靠证明无关时才可按正常查询语义排除，不能以解析失败排除。
4. 详情保留正常字段；内容解释失败时返回实际 URL/ETag、rawSource、raw、可可靠解析的字段及诊断，`complete: false`，明确未验证的组件选择，不冒充匹配。给出的选择器若有可确认的明确不匹配或歧义，仍按既有 NOT_FOUND/AMBIGUOUS_TARGET 处理。
5. 日历 get 的旧输入继续有效；新增允许 `raw: true` 且省略 uid/recurrenceId，表示按实际 URL 取得整资源原文、不选择组件。普通组件详情仍要求 uid，recurrenceId 不能单独出现；联系人已有可选 uid，不改变其正常结构化详情行为。不新增任意原文写工具。
6. `rawSource` 为 get/report，说明正文来自 GET 还是经 XML 解码的 REPORT；读取到的原文不被重新序列化。256 KiB 上限维持，超过仍 RESULT_TOO_LARGE、不截断正文或私自落盘/上传；不能声称所有大小的原文都可在一次工具调用返回。

### 第三步：插件发送前统一门控

- `calendar-write.ts` 与 `contact-actions.ts` 创建/更新：使用库现有编辑入口生成候选，合并已授权修正和受管修订元数据后，调用对应公开校验器；任何 invalid/unsupported 均不发送 PUT。校验失败以 `CONTENT_VALIDATION_FAILED` 返回问题与资源/目标上下文，不回显原始异常。
- 更新在刷新受管元数据之前，用库的源诊断识别拟刷新字段的非法值、重复项或无法确认状态；不能只在覆盖 REV 等字段后校验最终候选。正常合法字段刷新、可选字段缺省时初始化保持原行为；异常字段目前没有修正输入时返回修复能力不足、零 PUT，不新增确认开关或受管字段覆盖参数。源其他可明确修正的问题不因此一刀切拒绝。
- 库诊断应汇总可独立检查的问题，不因先遇另一个业务错误而跳过受管字段诊断；结构损坏导致无法检查时明确说明，不能将缺少诊断当作该字段合法。
- `mutations.ts` 只复用安全结果映射与流程，不实现校验规则。输出区分源记录问题、输入冲突、修复能力不足、最终校验失败和远端结果未知；生成最终候选前旧编辑器已拒绝时不得谎称新校验器已给出结论。
- 不把严格源校验放在所有编辑之前，避免阻止本来可表达的修正；但现有库已要求源结构/身份有效的入口仍遵守。一个组件多字段修正一次提交；兄弟组件错误使中间态被拒绝时停止并列出能力边界，不借假资源、序列化或插件字符串编辑绕过。
- 无改动分支也核对最终文本：有效才 unchanged，无效返回诊断，两个分支都零 PUT；有实际变化才维护修订。元数据更新之后再次得到的最终字符串才是发送检查对象，不对稍早版本检查后换内容发送。
- 更新仍比较调用方强 ETag，PUT 使用同一个已确认版本。DELETE 只执行身份、范围、授权及版本守卫，不要求内容先通过写回校验，不顺带修复正文。

### 第四步：回归、交付与授权顺序

- 库回归：四种合成兼容形态可读取原文、合法对照；错误 RRULE/根属性/既有提醒/时区、联系人日期/URI、兄弟组件错误、无法验证的合法输入和合法扩展分别归类；验证不改输入、不请求网络；包的三个公开子路径仍可正常消费，新增校验结果类型从对应内容入口导出。
- 插件回归：混合正常/失败资源返回原文及双重完整性；结构失败、时间投影失败、展开失败、UID 不匹配、无 UID 的 raw GET、搜索匹配未知、超限和取消；最终不合规（包括 no-op 与修订后状态）零 PUT，明确修正后通过校验才条件发送，冲突和结果未知语义不回归。
- 受管字段回归：源 REV 非法/重复而只改姓名时必须提示并零 PUT，不能被刷新为合法值后悄悄通过；合法 REV 仍正常刷新，合法可选缺省可正常初始化。异常元数据的 no-op 仍返回诊断，日历受管字段旧编辑器已拒绝的路径不为此放宽。
- 正常结果和已有输入兼容性单独核对；结果新增状态、日历 raw GET 的可选 uid 及更严格写门控须写明，不把行为变更当成纯内部重构。
- 顺序：批准本设计及两个仓库的具体实施范围 → 独立库实现/离线验收 → 另获授权发布可消费版本 → 插件锁定该版本并实现/离线验收 → 各自授权发布、安装、重载和服务验收。不先改个人配置或真实数据来证明方案成立。
- 本轮文档验证只检查 diff、链接、字段/示例、一致性和打包，不为证明设计文字运行无关生产端点、源码测试或编译。未来代码验收分别用库 npm run check/test/test:package 与插件 npm test/生产编译/打包及修改路径诊断；不能把本轮设计批准当作实现已通过。
