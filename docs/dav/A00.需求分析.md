# DAV 原生工具接入：需求草案

本专题讨论 pi-tsgw 消费独立 davkit 包的接入契约，不重新设计 DAV 核心库。当前状态、确认项和实施授权统一见 [任务清单](000.TODO.md)。

## 背景与目标

独立 davkit 已提供 DAV 通信、iCalendar 与 vCard 处理。插件承担账户配置、工具输入输出和业务编排，不再经过 DAV MCP 服务。现有 dav-mcp 作为功能与业务行为参考，不作为运行依赖。

已有服务可能保存不符合严格写入要求的日历或联系人资源。读取这些记录是识别、理解和修正问题的前提，不能因为结构解析或日期计算失败就屏蔽原文；反过来，读取得到原文不表示可以将其中的错误继续写回。

本轮明确“读时保真、写时合规”：读取保留已经取得的资源及解释状态；写回前确认必要修正，最终整份资源通过校验才发送。工具范围仍为既有 23 个，不新增任意原文 PUT 或自动修复流程。既有策略已经发布；本轮进一步补齐受管修订字段的显式修复能力。用户已授权插件本地实现、离线验证，并另行授权提交发布；不包含本机安装、重载或真实数据修正，不修改独立库。

## 功能需求

| 编号 | 需求 | 完成标准 |
| --- | --- | --- |
| DAV-R01 | 统一扩展配置与调用时检查 | 类型 → ID → 配置，ID 可跨类型同名；工具在兼容宿主上始终按需注册，不在注册阶段联网。缺 dav 组时调用返回配置指导，字段错误不影响其他有效类型；统一文件损坏或权限错误按整体文件错误报告。 |
| DAV-R02 | 枚举账户及实际集合 | 账户枚举不暴露认证信息；集合枚举区分日历与地址簿，返回真实发现结果，不猜个人路径。 |
| DAV-R03 | 查询、读取日程与已有重复实例 | 指定账户、集合和明确时间范围；区分资源、主件、已有例外与展开实例，结果不把部分失败或截断说成完整日程。 |
| DAV-R04 | 联系人列表、搜索、读取与编辑 | 保留多值、分组、参数及未修改内容；搜索范围和分页含义明确，不以局部结果证明全局不存在。 |
| DAV-R05 | 待办与日记的查询和读写 | 覆盖旧工具中对应业务能力；不将 VEVENT 的重复展开能力冒充待办、日记展开。 |
| DAV-R06 | 创建、定向修改与条件删除 | 只修改明确字段；资源身份与版本明确；冲突不自动覆盖，单个发生项不得误作整资源删除。 |
| DAV-R07 | 按需工具发现 | 工具默认不内联完整 schema，沿用宿主 codemode/deferred 能力，不新增 MCP 服务或工具加载器。 |

## 约束与非功能需求

| 编号 | 约束 | 验收口径 |
| --- | --- | --- |
| DAV-R08 | 配置归属、凭据与隐私 | Pi／Agent 核心及模型 provider 配置保留宿主现有入口；自定义扩展配置统一归 tsgw.json，按 imap/smtp/dav 类型分组，不再按功能新增独立文件；无 email 外层、逐项 type 或 defaultSmtp 配置字段。模型／OAuth／MCP 认证仍归宿主，DAV 账户与凭据的读取和迁移范围须单独确认；不把真实端点、正文或凭据放进测试、日志和示例。 |
| DAV-R09 | 核心职责与宿主兼容 | 复用已发布 davkit，不复制协议、解析、折行、时区或重复算法；不擅自提高整个插件的最低宿主或 Node.js 要求。 |
| DAV-R10 | 操作结果可信 | 区分成功、冲突、失败与远端结果未确认；取消、超时不等于远端未生效，不自动重发写入。 |
| DAV-R11 | 解释失败仍可读取源记录 | 已取得的资源若解析、字段投影或重复展开失败，仍返回实际资源定位、版本、原文和安全诊断；不丢弃失败记录，不将无法确定的发生时间或搜索匹配冒充已确认结果。 |
| DAV-R12 | 最终整份资源校验 | 创建或修改发送前校验最终候选资源，包括保留的旧字段、兄弟组件及修订元数据；已知错误或无法安全校验时不发送 PUT，不以目标字段正确、解析成功或成功展开代替整资源校验。 |
| DAV-R13 | 修正须明确且可执行 | 写前说明问题、建议修正及影响；有歧义先确认，不自动决定互斥字段优先级、不默默删属性。仅按已确认方案生成合法候选；现有接口无法表达修正时停止并说明能力边界。 |
| DAV-R14 | 显式修复异常修订信息 | 日程、待办、日记及联系人更新可表达经确认的受管字段修正；缺少明确修正仍零 PUT。同一目标的业务问题与元数据问题可合并修复，保留其它组件和非目标字段。最终整资源合规、强 ETag 与未知结果语义不变，不以删除记录或自动刷新代替修复。 |

## 非目标

- 不改变 davkit 的 DAV 通信职责或发布流程，不把核心库源码及校验规则复制进插件；必要的内容校验扩展仍归独立库，不由插件自行解析或修正源文本。
- 不增加后台同步、磁盘正文缓存、通知调度、跨账户聚合搜索、OAuth 或厂商私有路径试探；根地址只按标准服务入口发现。
- 不新增通用 JSON Patch、任意资源 PUT、凭据管理器、配置迁移器或多级配置优先级。
- 不开发 DAV 页面，不增加独立 UI 验收要求。
- 不承诺创建重复例外、编辑 RANGE、自定义 VTIMEZONE 编译、VTODO/VJOURNAL 重复展开等当前库未公开支持的能力。
- 不以本轮文档授权安装依赖、保存密码、运行真实端点验收、删除旧 MCP、发布或部署。

## 分层验收

1. 契约验收：工具范围、账户定位、配置授权和 Node.js 兼容方案明确，实施不需猜测这些边界。
2. 离线验收：隔离 agent-dir 和网络，用合成资源及本地 HTTP 服务验证工具、条件写入、内容保留及安全错误输出。
3. 策略验收：分别验证失败记录可读、资源读取与业务解释完整性、写前诊断、最终整资源不合规零 PUT，以及已确认修正后才可条件写入；删除仍按身份、范围与版本验收，不要求先修复将被删除的正文。
4. 发布与本机加载：离线验收后经独立授权提交并发布；更新本机与重载另行授权，npm 发布成功不等于会话已加载。
5. 真实只读验收：新工具实际加载并另行授权后验证发现、集合、读取、UID 和 ETag；不包含任何业务写入。
6. 写入与切换验收：另行授权限定对象及动作，再核验回读和旧服务切换，分别报告结果。

架构与接口口径见 [B00](B00.规划设计.md)，落地范围与验证入口见 [C00](C00.执行计划.md)。
