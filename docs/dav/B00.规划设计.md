# DAV 原生工具接入：设计草案

本轮在既有 23 个原生工具与统一配置边界内，设计“读时保真、写时合规”策略。原文保留与故障降级归插件编排；格式和内容语义校验归独立 davkit。本文新增的是设计，不表示现有运行版本已实现，也不构成修改独立库、发布或真实数据修正授权。需求依据见 [A00](A00.需求分析.md)，实际进度见 [任务清单](000.TODO.md)。

## 职责边界

~~~text
Pi 工具注册与权限钩子
    ↓ deferred，namespace=tsgw_dav
插件：配置 / schema / 查询投影 / 读改写业务编排
    ↓ 已发布包的公开入口
 davkit/dav     davkit/ical     davkit/vcard
    ↓
已有 CalDAV / CardDAV 服务
~~~

| 层级 | 负责 | 不负责 |
| --- | --- | --- |
| 宿主 | agent-dir 定位、工具注册与发现、调用权限和工具生命周期 | 不把其 MCP 凭据交给插件自行提取 |
| 插件 | 配置入口、账户定位、JSON 输入输出、业务字段映射、资源版本与错误语义 | 不复制 DAV 协议和内容算法，不另建调度器或工具加载器 |
| davkit | 请求、发现、查询、条件写入、日历和联系人解析编辑、有限重复展开 | 不读取插件配置，不决定用户授权或隐式迁移凭据 |

## 配置与认证提案

配置按归属而非功能数量划分，用户已确认统一扩展文件的方向：

| 类别 | 归属与位置 | 本轮边界 |
| --- | --- | --- |
| Pi／Agent 核心配置 | 模型、provider 及其参数继续使用宿主原有入口，包含现有 settings.json.tsgw | 不因由插件实现就迁入自定义功能配置，不改宿主格式与认证机制。 |
| 自定义扩展配置 | join(getAgentDir(), "tsgw.json")，按协议类型分组 | 顶层 imap、smtp、dav，各组为 ID 到配置的映射；ID 仅在同组内唯一。不设置 email/provider 外层，不搬迁模型接入参数。 |
| 模型／OAuth／MCP 凭据 | 仍交宿主管理 | 不因统一扩展配置而读取、复制或迁移宿主凭据。 |

不再增加 DAV 专用配置文件；现有邮件独立文件属于待退出的旧入口，不是新功能继续拆文件的先例。统一文件要求 0600。imap.tsn 与 dav.tsn 可同时存在，不要求全局 ID 唯一；每项无需重复 type。DAV 条目使用 url、user、password 与可选 timeZone，不沿用旧草案中 dav.caldav/carddav 的账户分层；不增加命令取密码或环境变量展开。统一示例见 [C00 配置草案](C00.执行计划.md#配置草案)。

**邮件迁移、DAV 本机配置保存和显式账户只读调用已分别获用户授权。** 该例外不扩大到模型或 MCP，不自动读取或迁移旧 DAV 凭据，也不因业务接入继续修改个人配置。服务发现实测与插件离线验收分开记录。

- imap、smtp、dav 独立配置，不要求 IMAP 与 SMTP 同时存在。缺组或空组表示尚未配置；缺配置、字段无效、未知账户与连接失败分别报告，不因某组错误停止其他有效类型。
- 泛型映射以顶层类型为键，对应具体配置类型与构造工厂；统一处理文件读取和组定位，各工厂只校验自身条目一次。复用现有协议实现，不增加逐功能文件读取器、空壳配置类或通用依赖注入容器。
- 不保留 defaultSmtp 字段。显式指定 SMTP 时只使用指定项；省略时取 smtp 组按对象枚举顺序注册的第一项，默认不取决于连接成功先后。无 SMTP 返回配置指导；连接失败不切换其他项。
- DAV 每次业务调用显式选择 dav 组内的账户 ID。集合查询和创建还须显式选择集合，不自动使用第一个日历/地址簿，不静默合并全部账户；日期解释继续要求明确时区，不使用主机时区兜底。
- URL 仅接受 HTTPS，不内嵌用户名、密码、query 或 fragment，不加不安全 TLS 开关。根路径按 kind 使用标准 /.well-known/caldav 或 carddav；明确非根服务路径则不改写。实际环境证明管理门户与 DAV 入口不同，服务发现因此允许最多三次同源重定向；每次由 davkit 以新入口重新发现，保证相对 href 的解析基准正确。跨源跳转拒绝转发认证，资源 GET/REPORT 仍不跟随跳转，不猜厂商私有路径或端口。
- 兼容宿主上工具按 deferred 方式注册，是否配置不决定工具是否可发现；调用时才检查相应类型，缺少配置时返回所需组和字段的本地配置指导，不要求用户在聊天中提交密码。统一文件 JSON 无法解析或权限不符时报告整体配置错误，不假装仍能读取其他组。
- 注册阶段不读取个人配置、不发现集合、不验证密码。配置在调用中加载，连接在实际业务调用中建立；已有邮件会话继续遵守重载/会话释放边界，不加文件监听器、隐式重连或自动切换。

## 运行兼容提案

已核对本地 SDK 1.4.0：宿主声明 Node.js >=22.19.0；davkit 0.3.0 声明 Node.js >=24。因此静态必需依赖加运行时判断，不能单独解决严格引擎检查下的安装兼容问题。

将 davkit 0.3.0 作为 optionalDependencies，沿用首批已验证的隔离方案。宿主满足已验证的 Pi 1.2+ deferred 契约时可先注册不依赖库执行的工具声明，调用时才检查配置、Node.js >=24 和依赖并动态加载实现。Node.js 22 或依赖被省略时返回 DAV 不可执行的原因，不提高整个插件的 peer 要求，不影响原有功能，不自动安装或降级。

代价是省略 optional 依赖的安装不能使用 DAV，需明确提示。替代方案是把整个插件基线改成 Node.js 24 并使用普通依赖，但影响面更大，须明确选择，不在此次接入中默认采用。Node.js 22 下普通及严格安装、Node.js 24 正常和 omit=optional 安装均须在实施阶段验证，不能以本机 24 代替。

## 工具与资源身份

建议一个命名空间 tsgw_dav；工具名称和业务清单见 [C00 工具清单](C00.执行计划.md#工具清单草案)。兼容宿主上始终注册工具声明，全部 exposure=deferred；调用才检查配置和相应协议能力。不提供输入密码的 connect，也不保留无实际会话意义的 reconnect。

- DAV 账户 ID 只在 dav 组内解释，与 imap/smtp 中的同名 ID 无关；公共集合工具必须带 kind 区分日历与地址簿。
- resourceUrl 与 UID 不等价；资源 URL 指向整份 ICS/VCF，日历还需 kind、UID 和可选的完整 RECURRENCE-ID 逻辑行选择已有组件。
- 展开实例保留原始发生身份，移动后的开始时间不能取代 RECURRENCE-ID；不把合成实例直接当作可独立写入的组件。
- 修改需携带调用方上次读取的强 ETag。先 GET 获取源文本，再核对版本并定向编辑；不能将最新 GET 的 ETag 自动替代旧版本来规避冲突。条件 PUT/DELETE 继续使用调用方确认的版本。
- 创建使用明确集合和随机资源名，核心库产生 UID；If-None-Match 防覆盖。创建入口不接受任意资源写入地址，修改/删除仅使用已定位资源的同源 URL，不在冲突后另建同内容资源。
- 删除表示整个资源，不提供伪装成单次发生项的 DELETE。混合类型或多个 UID 的资源不能按单个组件意图直接删除；需先澄清范围，缺少组件删除 API 时反馈独立库，而非插件切割原文。

## 查询、时间与完整性

- 事件列表要求明确 start/end，转换为库要求的基本 UTC 半开窗口，再使用 expandEvents，并按实际发生时间排序。解释 DATE/floating 时使用明确账户时区或调用覆盖值。REPORT 只筛选 VEVENT，不发送时间窗口：davkit 当前查询接口不传解释时区，服务端按其他时区解释 floating 时会提前排除本应命中的资源。接受读取所选日历全部事件资源的代价，再由库按调用时区与窗口过滤；单资源内容解释失败时保留源记录并标记业务结果不完整，不再因该失败丢弃整批已取得资源。协议、传输与结果总量失败仍明确报错，不返回 complete:true 的漏项列表。
- 列表和搜索只返回必要摘要，详情按需读取；结果说明请求的账户、集合、时间范围、完整性和截断。客户端 limit 不冒充服务端分页，不新增持久快照、游标缓存或后台同步。
- 库的 REPORT 数据经过 XML 解码和行尾规范化，只用于查询；保留式编辑必须 GET。遇到不支持规则、预算超限或读取失败，不返回看似完整的空结果。
- 联系人搜索完整查询所选地址簿，再对 FN/N/NICKNAME/TITLE/ROLE/ORG/NOTE/EMAIL/TEL 做本地不区分大小写匹配及电话规范化。使用 davkit 从 0.2.0 起提供的 components/items 解码叶值或标量 value，不以 rawValue 冒充已解码数据，不用 FN 服务端过滤漏掉其他字段。详情保留结构边界，明确不承诺旧文本逐字兼容。
- 联系人 phone 便捷字段只修改普通首项；若源首项显式声明 VALUE=uri，标量修改须改用完整 properties 替换，不猜测 URI 转换。null 仍可仅删除首项，不限制普通电话创建或其他首项的编辑。
- 正常日历与联系人对象不默认输出全部原文；显式请求或单资源内容解释失败时输出相应资源原文，不倾倒整个集合。需要参数列表等 Map 时先显式转换成普通 JSON 数据，不直接 JSON.stringify(Map)。

## 读时保真、写时合规

本节承接 DAV-R11/R12/R13，替代此前“任一内容解释失败即整批失败”的策略，不放宽写入质量，也不要求库替不规范记录猜测正确含义。

### 已有能力与职责选择

- `DavClient.get()` 已返回资源文本、实际 URL、ETag 和内容类型；`query()` 返回 XML 解码后的资源文本。`parseCalendar()` 已保留整份、组件和属性原文。即使解析函数抛错，调用方仍拥有传入的文本。因此原文降级只需改插件，不为此新增库 raw 模式、第二套解析器或通用原文读写工具。
- `expandEvents()` 是发生时间计算器，不是宽松读取接口，也不是写前整资源校验器。其失败可能表示数据错误、能力不支持、时区未解决或预算不足；插件不能一律归因为数据非法，更不能删除记录。
- 库负责独立、无修改的内容校验及稳定诊断；插件负责保留结果、输出与提示、用户修正授权和发送前门控。DAV 通信层继续只负责传输，不根据 Content-Type 调用日历或联系人校验器。
- 采用已发布 davkit@0.3.0 的 validateCalendarResource 与 validateContact 独立校验入口。旧日历编辑只检查部分语义，联系人解析/编辑也不是完整语义校验；最终发送须使用新入口的明确范围与诊断，不能将编辑成功、删除身份守卫、假更新或一次成功展开当作完整校验。
- 校验入口只检查文本并返回结构化结论，不修改或重新序列化内容。检查至少区分确定错误、检查能力不足与按扩展语法允许保留的内容；问题携带稳定代码及组件/属性定位，不嵌入真实值。新接口与既有读、编辑入口分开，不因加强写检查直接收紧宽松读取。

### 读取流程与结果完整性

1. 先取得资源文本和版本，再分别尝试结构解析、字段投影和事件展开；这些阶段失败不抹去已取得的内容。正常资源继续返回既有摘要或发生项，失败资源单独返回原文、可可靠取得的结构字段及安全诊断；不把未展开的存储主件塞进发生项数组冒充一次日程。
2. 列表分别说明资源获取是否完整和请求的业务结果是否完整。即使资源全取到，只要还有无法判定时间窗、UID、状态或搜索词匹配的记录，业务 `complete` 就是 false。搜索未能解释的资源作为匹配状态未知返回，不能视为不匹配。
3. 对某份资源展开失败，不在插件中拆分系列后另算例外或输出该资源的一部分发生项；保留库的资源级身份与计算边界。异常记录不被假定属于请求月份，也不据不完整结果证明不存在或完全空闲。
4. 详情的显式原文请求不依赖业务时间能否解释。没有可用 UID 时，可按已定位的实际资源 URL 请求整资源原文，不伪造组件身份；给出 UID/例外选择器时，能够解析出的明确不匹配仍返回 NOT_FOUND/AMBIGUOUS_TARGET，不用原文降级掩盖选错目标。无 UID 的原文模式用 completenessScope:"resource" 限定 complete:true 只指整资源获取，不声称已核对组件或完成业务投影；结构无法解析时同样不确认组件身份。
5. 原文说明来源：REPORT 文本可能经过 XML 行尾规范化；GET 文本才用于保留式编辑。原文只进入本次受授权工具结果，不进入普通错误、日志、缓存或仓库；它是外部数据，不是可执行指令。
6. 参数、权限、认证、取消、传输和 DAV 协议失败不降级成成功资源；超出既有结果上限仍明确报 RESULT_TOO_LARGE，不截断原文后冒充完整。读取成功不表示已通过格式校验或协议、认证的完整验收。

### 写前校验与修正

1. 创建或更新生成最终候选，更新仍先 GET、核对调用方确认的强 ETag 和精确目标。先诊断源中将被自动刷新的受管字段，再应用已授权的业务变更和明确修正，正常维护修订元数据，最后校验将实际发送的完整文本。
   - 合法受管元数据的刷新，以及规范允许缺省时的正常初始化，属于既有更新行为；非法值、重复项等源错误不能借刷新静默覆盖或合并。源诊断只用于识别这类修正授权缺口，不要求整个源先 valid 才允许构造已确认的修正候选。
   - 本轮不新增受管字段修复参数：异常 REV、DTSTAMP、LAST-MODIFIED、SEQUENCE 等若不能由现有输入明确表达修正，先提示并按修复能力不足停写，不用自动刷新代替确认。
2. 校验覆盖整份资源，而非只检查被改组件：包含保留字段、兄弟主件与例外、结构和关联约束。已知错误和无法安全校验的状态均不得发送 PUT；支持范围和不支持原因须由库明确，不将未知扩展一律判错或删去，也不宣称覆盖库未实现的全部 RFC 语义。
3. 错误诊断采用稳定代码、组件/属性定位与安全说明，不回显原始异常正文。修正建议与业务影响由调用代理结合原文说明；互斥字段保留哪项、截止日如何解释等有歧义事项必须先确认。工具不暂停等待人工输入，不建立修正会话或自动纠错器。
4. 读取源数据有问题不意味着必须在编辑前先拒绝一切操作：允许按明确方案构造修正后的候选，但最终必须合规；不能借此提供关闭最终校验、任意 raw PUT 或未授权的兄弟组件改写。现有定向接口无法表达修正，或身份/结构无法可靠确认时，返回原文和边界说明，停止写入，不在插件切割原文。
   - 本轮维持一次 update 精确编辑一个已存储组件/联系人，不新增多组件修复参数或通用批编辑。日历的同一组件多项问题可在一次 edit 内明确修正；多个组件同时错误可能使逐次编辑均被现有库拒绝。该已复现边界必须明示为修复能力不足，不能声称只加最终校验就已支持任意坏资源修复；如需扩展，另行设计单资源修正能力，而不是输出关闭校验的中间态。
5. 即使只改标题，已确认错误也不能原样写回。候选未变仍执行校验；不合规不返回仿佛已验收的 unchanged，合规且无变化才返回 unchanged、不刷新修订、不发送 PUT。客户端校验通过不消除后续版本冲突，条件头保持不变。
6. DELETE 不写回正文，不强迫先把待删除的异常内容修成合法；仍须明确删除授权、完整资源身份/范围守卫及强 ETag。身份无法确认时不能只凭 raw 删除。

### 明确不采用的替代方案

- 不要求先修好服务器数据才允许读取，不屏蔽异常资源后声称查询完整。
- 不默认增加互斥字段优先级、截取日期或自动规范化整资源；这会把读取变成未经确认的语义修正。
- 不把最终校验规则复制进插件，也不把传入任意文本的 DAV update 当作业务修复入口。

## 调用与结果策略

- 不维护共享的“当前调用 signal”。按调用创建轻量 DavClient，以 fetch 注入闭包合并工具取消信号与库的 30 秒超时；不复制协议或响应解析。
- 使用宿主 outputSchema 和 structuredContent，同时给模型安全文本及错误标记。annotations 仅作权限提示，不自称已替用户批准创建、修改或删除。
- 冲突返回 CONFLICT；写入发出且尚未取得确定结果时，若网络断开、取消或仅收到待处理响应，返回 REMOTE_RESULT_UNKNOWN，附目标 resourceUrl 与方法；创建另附已生成的 account/uid 及日历 kind，以便直接 GET 核对，不依赖列表或展开时区。身份仅留在本次调用的上下文，不解析写出正文或持久保存。不承诺未发生、不自动重试或补偿。已取得认可成功状态后，不因响应体清理或随后取消降为未知。写工具只返回小型身份、版本和 outcome，不在内部写后回读；调用方后续回读与写入结果分开报告。无内容变更返回 unchanged，不发送 PUT 或刷新修订。
- 不建立全局业务缓存或重复请求去重设施；确有新需求再讨论。地址、正文和协议原始异常不进入普通日志。
