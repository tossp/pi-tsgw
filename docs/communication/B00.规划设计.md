## 2. 推荐架构

tsgw 同包通信入口 → 本机会话协作核心 → Relaycast 原生 REST／WebSocket 消息桥 → 既有中央消息服务 → 对端消息桥与主会话

本地主代理 → 宿主 Agent 工具 → 子代理 → 宿主通知主代理 → 显式提交任务结果

- 通信入口只负责配置、注册与生命周期，不绑定 tsgw provider。
- 会话协作核心拥有身份、任务关联、有界队列和本地记录，不负责模型推理实现。
- 原生消息桥负责私信、历史补收和投递；使用本插件有版本协作信封，不建设标准 A2A 服务或大型协议转换层。
- 中央消息服务负责认证、消息保存与分发；通信客户端构造有效会话目录，本地任务核心拥有协作状态，不将这些能力归给后端。
- 主代理负责理解、查询或委派、判断来源和结果完整性；宿主继续管理子代理。
- 子代理默认不是外部端点，不另设与主代理竞争的接待实例。

## 3. 协议与中央路由决策

### 已确认路线：Relaycast 原生消息桥

首版使用原生私信传递有版本的请求、接收确认、状态查询／响应、等待输入、补充输入和结果；使用仅含会话元数据的专用发现频道承载公告。字段和任务语义属于本插件最小协作约定，不宣称标准 A2A。原先等待标准 v1 网关互通的门槛取消，不再比较或部署第二个中央服务；标准 A2A 仅为后续独立审批的适配方向。

| 可复用能力 | 客户端责任及验证门槛 |
| --- | --- |
| POST /v1/dm，data 结构化持久化，历史分页读取 | text 内完整序列化版本化 JSON 信封，data 只放辅助标签，避免 SDK 事件丢 metadata；平台消息 ID 与应用消息 ID 分开保存，REST 历史用于补收和核对 |
| Agent token 换 node token，主动连接 /v1/node/ws | 不需要设备公网入站；认证 token 不写日志。官方 SDK 使用全局 WebSocket，认证参数、运行时兼容及依赖需核验，不假定已有短期 ticket |
| 持久 delivery、序号与累计 ACK、/v1/deliveries 补收 | 平台 ACK 不等于应用可靠接收；官方 SDK 不等待异步回调就 ACK，因此首版独立以 REST 历史＋本地持久 inbox／游标补收，不能只依靠未 ACK deliveries；ACK 前后崩溃窗口必须测试 |
| 私信 HTTP Idempotency-Key，源码 direct DM claim 为 24 小时 | 固定应用 messageId、重放期限及接收方去重独立存在；不得靠平台 24 小时机制承诺任意期限恰好一次 |
| 专用发现频道的消息与历史 | 公告是元数据控制流，不唤醒模型；客户端按时间与活动版本构造有效目录，后端没有公告 TTL／CAS，不承诺中央物理删除 |

原生接口证据见 [原生消息桥接口依据](C00.执行计划/原生消息桥接口依据.md)，此前已部署端点的实测见 [现有接口核验记录](C00.执行计划/现有接口核验记录.md)；源码能力不等于新路线运行验收。仅采用完成联动查询所需的信封，不扩成完整 A2A 克隆、通用编排器或独立执行器。

### 设备传输身份与连接所有者

每台设备一次性由既有管理端供应一个专属 Relaycast Agent 身份和 token，再由插件在消息体中按 Pi 会话 ID 分流；不为每个新会话申请新 Agent。设备 ID 与服务端认证 Agent ID 的绑定须在供应时固定，消息自报设备名不构成认证。专用发现频道也由该管理流程预置并授予已供应设备访问；插件不持有 workspace 管理 key，不自行创建工作区或新增供应服务。P0 已获授权完成一次性 Agent／发现频道供应，密钥按 join(getAgentDir(), ".secrets", "relaycast.key") 保存，结果见 C00 的 P0 接口验证 §5；不在插件内自动供应，凭据轮换仍未授权。

同一宿主进程、同一设备身份及同一不可变传输配置快照共享一个传输实例，按会话引用计数；各会话仍独立维护任务与投递。不同快照不得静默共用连接或凭据；与该设备在用实例冲突的新快照停止初始化并报告需重载，旧快照最后一个引用释放后才可初始化新快照。传输实例拥有 node 连接、发现订阅及 inbox，单个会话退出只撤销自身注册，最后一个引用结束才释放共享资源。宿主进程重启不等于恢复主会话。设备身份在跨进程间取得本地排他所有权，未取得者不得抢接同一设备消息；多进程同时服务一个设备身份的分流方式仍须验证，不能因 node/provider 仲裁就宣称业务锁成立。若实际多进程需要多入口，采用明确的不同持久设备实例 ID，不自动覆盖原身份或悄悄增设常驻代理。

对外仍按“设备 ID＋会话 ID”寻址，不使用 Relaycast Agent 名称替代会话身份。一次性设备供应不是逐会话接待名单；供好设备后，新主会话自动注册，具体接收仍检查运行实例和近期资格。

## 4. 身份、发现与绑定

- 规范身份为设备标识与 Pi 会话 ID 的组合。ownerEpoch 与 instanceId 专指该具体会话接待实例：每次重载、替换或关闭后重开，先原子递增该会话的持久 ownerEpoch，并生成新 instanceId，再接单／公告；即使共享设备连接没有断开也必须换代。单纯 WS 重连不改变仍运行会话的接待代次。传输内部的连接重试代次仅防迟到回调，不作为消息目标代次。
- 设备标识首次启用时自动生成随机标识并原子持久保存，允许显式覆盖；不采用端口、IP 或最后活跃时间作为稳定身份。hostname 仅作默认设备显示名。配置复制到另一设备时必须避免复制自动身份；检测到同身份冲突则停止接待并提示修复，不静默抢占。
- 启用通信后自动登记最近 3 天更新的主会话，不设逐会话接待名单或设备／项目白名单。用户可见目录仅展示设备标识、设备显示名、Pi 会话 ID、名称、项目目录、最近消息时间及在线／忙碌能力状态；线上公告另含 ownerEpoch、instanceId、activityRevision、presenceRevision、lastHeartbeatAt 等合并与路由控制字段，不公告聊天正文或会话文件路径。名称变化不改变身份。
- 近期窗口为连续 72 小时，now - lastMessageAt >= 72h 时退出目录；新真实用户／模型消息更新后重新加入。心跳、目录刷新、协议确认、文件 mtime、重开页面及重命名均不续期；真实远端任务产生的用户／模型消息计入，纯通信状态消息不计入。此窗口仅影响目录与新接单，不表示已完成、取消或删除项目。
- 区分 lastMessageAt 与 lastHeartbeatAt：前者决定目录资格，后者决定在线状态。近期会话可显示离线，但不因此承诺可唤醒；只读枚举最近会话元数据，不为扫描而加载全部历史会话或传送正文。元数据枚举接口、时间提取及更新时间追踪须在 P0a 核验；没有可用接口时明确报告缺口，不假称已同步历史。
- 公告通过专用发现频道发布元数据，心跳与公告均不触发模型回合。正常关闭尽力发送 withdraw，突然失联由接收方按心跳超时派生离线，不依赖对端补发离线消息；满 72 小时无消息时，各客户端在每次列目录和接单时过滤，不能依赖设备在线撤销。后端可以保留原公告，原始频道不是工具直接展示的目录，也不自动执行物理清理。重新更新后重新公告；自动设备标识不是认证凭据。
- 项目目录、会话名称及可选 Git 分支仅作发现信息；不把跨设备相同路径合并为同一项目。
- 会话文件路径只保留本地；不自动向目录公布。项目路径允许按配置缩减披露。
- 本插件的 contextId、taskId 与本地会话身份分别存储；协作上下文不包含对方完整历史。
- 目录展示窗口内会话，明确区分近期可发现与在线可接单。未知、离线、歧义或过期目标明确报告，不回退到最新会话；仅知道某历史会话 ID 不等于可恢复其执行实例。
- 对同一规范身份的并发实例实行排他接待；无法确认归属时拒绝新接单，不容许两个主会话重复执行。

### 活动计算、角色与到期竞态

首版固定 72 小时，不提供窗口配置。lastMessageAt 使用已持久化消息的原始时间，按下表取最大值；历史扫描与在线跟踪共用同一分类算法。未来时间异常不直接延长公告，报告并核对；没有合格消息的空会话不公告。角色、来源与消息时间的可获取性属于 P0a 门槛，不用文件 mtime 或宿主列表的回退时间替代。

| 消息类型 | 是否计入活动 |
| --- | --- |
| 用户实际输入；已接受并持久注入的远端任务或补充输入 custom 消息 | 是；远端消息按本地持久注入时间，不按对端自报时间 |
| 本地工作／真实协作的成功 assistant 内容、任务结果与有效等待问题 custom 消息 | 是；采用消息持久时间 |
| 工具结果、纯工具调用消息、错误／中止且无成功内容的回复 | 否；相关真实输入本身可计入 |
| 心跳、ACK、目录状态、重试提示、维护消息及其衍生 assistant 输出 | 否；维护流量不得触发模型，历史记录须保留来源分类以便复算 |
| 单纯创建／打开／重命名／刷新／无消息会话 | 否 |

在线注册与历史枚举均排除宿主子代理。适配器先读取宿主子代理元数据／运行标识确定角色；子代理即使加载扩展也不公告、不接单、不注册通信保活。通用 Pi 无子代理宿主可识别为普通主会话；存在子代理宿主而角色不可确认时，标为未知、不自动接待并报告能力缺口，P0a 验证标识的可用性，不以路径猜测角色。

每次合格活动递增该会话的持久 activityRevision；活动元数据与在线状态分别合并，presence 不覆盖较新活动。每个会话接待代次内，心跳及 online／busy／offline／withdraw 变化严格递增 presenceRevision，重发同一消息保持原版本；同身份单写者约束必须先成立。目录按 (deviceId, sessionId) 比较，较大 ownerEpoch 的公告替换旧接待实例，同一 ownerEpoch 必须匹配 instanceId，再比较 activityRevision；同代次不同 instanceId 视为冲突，不猜测取最新。在线状态先匹配 ownerEpoch／instanceId，再按 presenceRevision 合并；同版本异内容报告冲突。离线标记与撤销仅能作用于其指定 ownerEpoch、instanceId 和 activityRevision，且必须通过 presenceRevision 比较，旧实例撤销不能覆盖新实例公告或新活动。后端仅追加消息，不依赖其提供 CAS；到期是各客户端在读取时按原始 lastMessageAt 计算的派生状态，不能写入无条件删除新公告。初次订阅与断线恢复从发现历史重建，跨页保持版本最大值；历史或权限不足以建立完整视图时明确标为不完整，不能将未见目标判成不存在。发现重放、分页范围和容量限额列入 P0a。新任务接受事务重新检查本地近期资格、角色及运行归属；与到期使用同一串行边界，不仅信任目录缓存。已接受消息的幂等恢复走记录路径，不作为新接单。

首版设计参数为每 30 秒发送心跳、最近有效心跳距当前时间达到 90 秒即判离线，忙碌也续发；这不改变 72 小时活动窗口。历史重放按平台持久消息时间计算新鲜度，不能以重放的本地接收时间刷新心跳；时钟或时间字段无法核实时标记状态未知，不宣称在线。较新 online 也须通过新鲜度检查，较旧 presence 不覆盖较新状态；发现频道周期性对账弥补事件缺失，参数与平台时间可用性须在 P0a 验证，改变数值先回写设计。

收尾释放前重新检查近期资格及在途任务；若收尾产生合格消息，应取消到期收尾并重新公告／维持保活。只有仍过期且无执行或待发送结果需要保留时才释放。等待输入任务本身不无限保活模型。满 72 小时退出后，新 request 与新补充输入均返回 session_paused，不接受入执行队列、不自动重试或激活；只有用户在本地继续对话产生合格新消息、重新取得近期资格后才可继续接待，仅重开页面／会话实例不足以恢复资格。原记录查询和结果读取仍按 §6 允许，不唤醒模型或续期。此前已接受的任务执行／结果回报属于收尾，仍按活动分类及释放前复核处理，不等于放开新的远端续问。

## 5. 主会话执行闭环

1. 发送方选择精确会话，先持久记录目标、原始 messageId、请求内容摘要与正文、发起会话及不可延长的有效期，再发送查询。
2. 接收方完成认证、授权、体积与有效期校验，将任务可靠记录后才确认接收。
3. 投递带来源及任务 ID 的自定义消息；明确它是对端查询，不是用户批准。
4. 忙时 followUp 排队，空闲时触发主代理；Pi 的投递函数返回不是持久接收确认。
5. 主代理可直接查询，也可正常调用宿主 Agent；模型不得被要求虚构不存在的子代理工具。
6. 子代理由宿主回传主代理；已消费结果不再触发重复通知，通信层不另做一份回弹机制。
7. 主代理显式提交对应 taskId 的结果或失败，或按 §6 请求补充输入，附来源和不确定性；不靠 agent_end 或最后一条文本猜测完成。
8. 发送方通过原生私信中的任务查询／响应或结果信封获取结果，持久接收后再投递回原始发起会话。结果不是新任务，不自动要求礼貌性回信；查询和平台控制通知不唤醒模型。

一个会话可挂起多个任务；不使用单个 currentTaskId。模型可查询待办、分别提交结果；提交时校验任务归属、调用会话和终态，过期会话回调不得完成别人的任务。

## 6. 状态、持久性与超时

- 采用本插件状态 submitted、working、input_required、completed、failed；取消未实现时明确不支持，不预先增加已取消成功的承诺。状态只是本地协作记录，不是 Relaycast 或标准 A2A 状态。
- 本地保存任务与会话映射、消息去重键、期限、终态结果及发送状态；stateRevision 由接收／执行侧该 taskId 的任务记录唯一拥有，每次任务状态变更原子递增，accepted、task_state 和 result 回传同一权威版本；发起侧仅保存 remoteStateRevision 镜像，不自行递增，发送／未确认等本地投递状态独立保存。仅更高版本可推进或覆盖状态；同版本一致消息仍可补齐已知终态尚未保存的结果、完成查询关联及恢复回执，但不能重复唤醒模型；同版本矛盾内容报告冲突。已确认终态不可改写；不保存认证头、签名 URL 或完整会话历史。
- 去重键含已认证调用方与 messageId，绑定目标及请求摘要；同键异内容冲突拒绝，同键同内容返回原任务，不重复唤醒。任务接受与本地记录需要原子边界。
- 已取得 taskId 时发送 task_query 信封，接收方返回 task_state／result；确认丢失且尚无 taskId 时，用 task_query 的 originalMessageId 查询原 request／input 的接收记录，返回原 taskId／状态。查询与原调用身份绑定，不生成新执行。原 request 的网络重传仍必须复用应用 messageId 和 Idempotency-Key；平台可能只返回缓存发送回执而不再次投递，因此不能只靠重发 request 触发应用重发 accepted。无记录仅表示当前没有可靠接收事实，发起方不能据此自动另建任务。
- 执行消息恢复只重放原消息，不生成新 ID 或延长原有效期；状态查询有独立 query messageId 及有界期限，不改变任务、允许有界轮询，每次查询的网络重传也复用其原键；先确认对端支持上述去重，再进行有界恢复。发送端重启也使用原记录。超时不证明执行停止，取消只有得到执行层确认才报已取消。
- 入站任务与本地回复待发送记录持久化；断线可再次查询或补发同一终态，不重新运行查询。存储失败则拒绝接收。
- 重启处理见下表；进程中断不自动重跑。执行结果不确定以 failed 加明确说明表达，不将其冒充 completed 或执行已取消。
- 原生消息层可能保留离线私信，但第一期不承诺离线任务接单：未收到对端 accepted 仅表示发送／接收未确认，不自动分配已执行状态。新请求携带由目录取得的目标 ownerEpoch／instanceId；没有在线接待信息就不发起。实例已换代或原请求过期时，后到的新任务明确拒绝，不在重开时静默执行；已接受消息恢复先去重，不用新实例门槛挡住原记录查询。
- 结果保留期与去重保留期分别声明；去重记录至少保留到原请求有效期加时钟容差结束，未过期记录不因容量不足提前驱逐，容量满则拒绝新任务。首次请求的有效期也受本地最大期限校验，不能任意延长。
- 超过有效期的旧消息直接拒绝，不因结果／去重记录已清理而重新执行；查询消息自身超过有效期时返回 expired；结果保留期届满后返回 result_unavailable，任务期限到期产生的失败记录在结果保留期内仍可查询。重发不延长期限或保留期；N03 的有界保证与 R09 的去重承诺适用同一窗口。
- 日志只含关联 ID、阶段与脱敏错误，记录目录应受本地文件权限保护。

### 退出目录后的记录可达性

目录资格只控制发现与新执行，不删除任务记录或改写设备通信身份。存在目标主会话运行实例时，即使已退目录，也允许通过已保存的 Relaycast 对端 Agent ID＋设备／会话身份，以查询私信取回已接受任务和终态，均不启动模型、不重新公告。先识别已接受消息，再判断是否属于新接单。

首版不新增脱离会话实例的常驻记录服务。共享设备传输可以接收并持久保存待转交消息，却不代替已回收会话回答任务状态或创建模型实例；目标会话实例回收、显式关闭、设备停止或断网时，记录暂不可远端查询。先前结果若已在发送方可靠保存，可直接本地查看；否则需重新打开原会话恢复记录路由，保留窗口内可取回，不能把暂不可达误报为不存在或已过期。查询不要求目标重新进入有效目录，也不续期；发送方持久保存对端身份和标识，不依赖当前发现列表。查询自身不续期，若补齐此前尚未入会话的真实问题／结果，其首次实际注入按活动表计入，重复查询不能重置该通知或再次续期。P0a 验证未入有效目录的运行实例可接查询，以及回收后不可达、重开后可查询。后端保存私信不等于自动恢复任务。

### 补充输入接收顺序

尚未接受的新 input 必须针对当前接待实例。task_query 的已接受任务响应附当前 ownerEpoch／instanceId、近期资格、在线状态及可否续问；这些路由信息不进入任务状态版本，实例重开或取得资格时即使 stateRevision 不变也可刷新。发送方在重开／旧实例拒绝后先查询取得当前实例再构造新输入，不能把旧 input 改字段后沿用同一 messageId；若旧消息可能已被接受，先按 originalMessageId 查询，未确认前不得另发同一续轮。仍过期返回 session_paused；无实例暂不可达；仅实例已重开但仍在近期窗口内，可刷新代次后续问。

先认证、校验调用方归属和消息内容／期限，再查消息去重记录：已接受且内容一致的原消息在重放有效期内返回原任务当前状态，不再应用首次接收的 input_required 门槛；异内容冲突拒绝。尚未接受的新补充消息必须携带其回答的 expectedRoundId，与接收端当前等待轮次和 input_required 状态原子比较，再检查近期与在线资格及目标 ownerEpoch／instanceId，匹配后持久记录、递增轮次并转换为待投递；旧实例的未接受 input 返回 target_instance_mismatch，不能自动改投。expectedRoundId 缺失或不匹配均拒绝，不推断为最新等待轮次。两个不同 messageId 回答同一轮次时仅一个可成功；即使第一条处理后很快再次等待，迟到的另一条仍因期望轮次过旧被拒绝。expectedRoundId 是本插件协作信封字段，具体 text 承载和 REST／事件完整保留须在 P0a 验证，不伪装成 Relaycast 原生任务字段。已接受消息重放仍先去重，不重新检查等待轮次。

### 请求补充输入与等待通知

执行侧提供独立“请求补充输入”操作：主模型提交 taskId、当前 roundId、问题 payload、稳定 operationId 及关联子代理／停止声明。幂等键为执行会话身份＋taskId＋operationId，问题、轮次及声明按结构化字段值比较，不因 JSON 键序或空白不同而冲突；操作记录与任务／轮次原子持久保存，保留规则与下节恢复索引一致。先校验调用会话归属再查幂等：同键异内容拒绝 conflict；同键同内容返回原操作已接受事实与当前任务状态，不再进入等待、写通知或递增 stateRevision。若任务期限已到，先完成到期转换再报告当前 failed；轮次已推进／已有终态时不重新激活旧等待，重启后沿用相同记录。

对于未命中的新操作，原子检查当前 roundId、期限、非终态、近期资格及必要子代理已停止，当前状态必须为 working，才保存问题、转为 input_required、递增 stateRevision 并写入待发送通知。已经 input_required 时，新 operationId 无论问题是否相同均优先返回 conflict（即使同时暂停），不能改写既有问题；只有原 operationId 的同内容重放可取回原操作。未等待的 working 任务满 72 小时已暂停时，新操作返回 session_paused，不进入等待、不发送通知；被拒绝的问题不计活动，已有任务仍按收尾规则完成或失败，不靠请求补充输入本身恢复近期资格。首次接受 request 分配 roundId=1；进入等待不递增 roundId，只有后续 input 成功接受才递增，问题只能在下一轮 working 后重新提出。

input_required 通知带 taskId、contextId、roundId、stateRevision、问题及原 request messageId，按通知投递规则可靠保存并呈现给发起主会话。发起侧从问题通知或查询结果取 roundId 作为 expectedRoundId，不能自行推导。task_query 返回等待问题及相同状态版本，但自身不唤醒模型；查询发现尚未保存的问题时可补齐相同逻辑通知，按通知键去重而非按查询 ID 触发新回合。已知更高版本已离开等待态的旧问题只保留记录，不注入模型。同版本缺载荷不算已完成通知，允许补齐；内容矛盾报冲突。input_required 不是终态，不适用终态结果保留期；执行侧持久问题随任务记录保留，失联可轮询取回，通知发送重试仅用原消息 ID 和有界期限，不无限延长。

### 恢复索引的保留窗口

已认证调用方＋原 request messageId → taskId，以及每条已接受 input messageId → taskId／roundId，作为任务／轮次记录的恢复索引持久保存，不仅放在短期去重表。非终态任务不得清除恢复索引；终态索引至少保留至 max(taskExpiresAt＋时钟容差, resultRetainUntil)，resultRetainUntil 从实际终态持久时间加结果保留时长计算，不能仅用“任务期限＋固定天数”估计提前完成或晚处理的记录。去重保留结束不妨碍非终态或结果保留期内以 originalMessageId 查询；结果已清理但索引仍在保留范围时返回 result_unavailable，不误报无接收记录；索引查找不重放或执行过期原消息。查询消息使用自己的有效期，记录已清理后明确不可用，不能据此创建新任务。

每个任务保存固定 taskExpiresAt，每条输入保存独立 replayUntil（不得晚于任务期限）；新 messageId 不延长任务总期限。去重返回只返回当前记录，不重复投递。每轮记录 roundId、输入 messageId、投递前标记及状态，使用下表逐轮恢复；上一轮完成不代表新一轮已执行。同任务续问保持同一 taskId/contextId；信封版本及每轮幂等记录显式持久化，不从平台消息 ID 推断任务。

### 任务总期限与终态

任务总期限与 72 小时目录窗口、单消息重放期限、结果保留期分别计算。处理接收、首次／续问投递、提交结果和重开恢复时，均先检查任务是否已终态；非终态若 now >= taskExpiresAt，按下表原子结束，优先于后续恢复表。期限边界与结果提交串行判定，到期后的结果不得复活或覆盖任务。

| 到期时本地阶段 | 对外状态及后续行为 |
| --- | --- |
| 已接受但尚未投递／排队待投递 | failed，说明期限内未启动当前轮次；不得首次或再次投递 |
| 等待补充输入 | failed，说明输入期限结束；不得继续报告 input_required 或接受新的补充输入 |
| 即将投递／已投递／执行中 | failed，说明任务超时、执行停止未确认；不冒充已取消，不保证工具或子代理已停止，保持已知执行收尾所需状态并禁止自动重跑 |
| 已有终态 | 保留原终态，不改写已完成结果 |

同消息幂等取回不得绕开重放期限；task_query 在结果保留期内仍可读取超时失败。结果保留期限从终态持久时间计算，任务到期不立即删除结果或去重记录。若进程在到期时未运行，重开后先补做上述转换，记录实际处理时间及原任务期限，再返回查询；迟到子代理回报可供人工核查，不自动完成旧任务。

### 重启与续问状态

投递前必须先持久标记“即将投递”；只有仍为“已记录、未标记投递”的任务才可证明未执行。模型投递与工具执行不宣称存在跨组件原子事务。

| 本地记录 | 重新打开会话后的对外状态 | 后续行为 |
| --- | --- | --- |
| 已记录、未标记投递 | failed，说明服务中断且尚未启动 | 不自动投递；新尝试须明确发起新任务 |
| 即将投递／已投递／执行中，无终态 | failed，说明执行结果不确定 | 不自动重跑；先核对已发生的行为，再决定新任务 |
| 等待补充输入，且无后台执行 | 保留 input_required | 仅未到任务总期限时保留等待态；原调用方先查询当前接待实例及资格，再以新 messageId、原 taskId/contextId、expectedRoundId 和当前实例补充输入；已退目录时须先由用户在本地继续对话，不能靠远端输入恢复，任务期限到达则先转失败 |
| 已有终态 | 保留原终态及保留窗口内结果 | 不重启任务；迟到子代理报告不得覆盖或重新开启终态 |

首版不增加子代理拦截器：由主模型在提交等待输入或结果时声明本任务当前轮次的关联子代理（子会话 ID，以及宿主可用时的运行完成标识）与执行已停止状态。taskId／roundId 必须显式提交，不从单个会话当前任务推断；resume 视为新的子代理运行，旧运行回报只供参考，不能自动完成新轮次。扩展校验记录归属、轮次和终态；有宿主状态可用时交叉检查，已知本轮必要子代理仍运行则拒绝等待输入或正常 completed 提交；任务超时或失败可进入 failed，但明确 executionStopConfirmed=false 并保留关联运行、收尾信息，不将通信终态冒充实际执行停止。没有可靠关联／状态接口时只能依赖模型声明，必须展示未核实，不能承诺可靠检测所有挂起子代理；此局限符合首版模型判断边界，不建立第二套执行器。补充输入只允许原调用方或获准主体；终态之后的追问在同 contextId 下创建新任务，不复活旧任务。第一期不支持的取消或订阅能力明确返回不支持，不提前承诺执行会被中止。

### 发起侧通知的本地投递恢复

结果持久接收与已注入会话分别记录。每条 result／input_required 与原 request 关联；accepted 未到而通知先到时，先校验本地原 request 和认证来源，再查询核实 taskId 绑定，未确认期间保留原通知而不丢弃或注入。发起侧在同一持久事务中保存通知载荷、任务状态及 pending_injection 记录。逻辑通知键为执行方身份＋taskId＋roundId＋kind＋stateRevision，附原 messageId 和稳定 notificationId；不同平台 ID、重发或查询补齐均合并到同一键，冲突拒绝，不产生第二次待投递。

result 的 received 只表示载荷和本地通知队列均已可靠保存，不表示模型已读取或处理。执行方可停止网络重发，本地通知恢复不再依赖重发；input_required 不新增相互 ACK，靠查询补收。投递前持久标记 injecting，把 notificationId 放入宿主 custom_message.details；仅在独立重新读取已存在的会话文件、确认原发起分支对应记录已保存后标为 injected，不能把 ctx 内存条目、message_end 或 sendMessage 返回当作成功。injected 表示已进入会话记录，不表示模型推理完成；busy 时按宿主 followUp 队列处理。

| 本地通知记录 | 重新打开原发起会话后的处理 |
| --- | --- |
| pending_injection，尚未标记投递 | 按原 notificationId 投递；结果不创建新任务，过时等待问题不唤醒 |
| injecting，原发起分支的可重读文件历史存在对应 notificationId | 补记 injected，不再次注入；旧分支记录不能冒充当前分支通知，差异显式提示，不自动跨分支重投 |
| injecting，宿主能可靠证明尚未投递或已拒绝 | 回到 pending_injection，按原通知恢复 |
| injecting，无法确认是否已投递 | 标 injection_unknown，停止自动注入，显示“结果／问题已保存、会话通知未确认”；允许用户查看记录后明确决定补投，不重跑远端任务 |
| injected | 重复载荷最多恢复网络 received，不再自动唤醒 |

宿主是否保留并能查询 notificationId、忙时待投递的持久性与证明未投递的接口均须 P0a 验证；历史暂未见标记本身不等于未投递。不具备可靠接口时采用上述显式未确认降级，不冒称跨存储恰好一次；关闭、回收或通知队列满也不能静默丢弃，容量不足时不得确认已可靠保存。问题与结果查看操作展示本地通知状态；入站通知保留至明示的本地通知保留期限，未确认项不得静默驱逐，容量与期限在实现审批前补齐。即使对端结果保留期届满，本地已收到的通知仍按本地记录保留规则处理。

### 平台投递与应用消费

私信 text 是协作信封的唯一完整正文，data 不承担必须字段；平台服务端 sender Agent ID、私信参与者和目标会话共同决定路由，未知版本、非协议文本或缺少该 kind 必需字段的消息不唤醒模型；此前传输探针遗留的合成公告没有完整实例／活动版本，不得进入有效目录，也不能因来自已认证设备就省略 schema 校验。信封包含 protocol/version、kind、messageId、correlationId、来源／目标身份、contextId、taskId／roundId（适用时）、固定期限及 payload；查询响应必须对应已发查询或既有任务。accepted 和 task_state 不直接触发推理，合法 request／input 与需要汇报的 result／input_required 通知才进入模型；查询补齐问题或结果时复用同一逻辑通知，不能因换查询 ID 重复唤醒。最小 kind、字段及错误表由 C00 固定，不能仅用自然语言猜测消息类型。

平台自动 ACK 可能早于本地异步写盘，不能将其当作本地接收事务。实时事件只是快路：收件箱先按平台消息 ID 原子落盘，再交任务事务；REST 私信会话列表／分页历史是独立的补收依据。按传输配置作用域＋DM conversationId 分别保存历史游标，发现频道也独立保存游标，不能让 P 会话进度跳过 Q 会话未读消息。会话列表只用于枚举，不代表其下消息已消费；已核对 10.4.2 该列表无分页游标，应不传 limit 获取全部参与会话，超出本地容量须标不完整而非静默截断；新发现 DM 从可读历史起点建立基线，首次连接及周期性对账完整枚举允许范围，无法确认完整覆盖则标不完整。每个流分别分页，按服务端支持的顺序完整落盘后原子推进连续边界，具体分页方向／边界在 P0a 核验；以最新一条消息替代连续边界是禁止的。游标不随 WS ACK 前进，只在对应流所覆盖的连续历史范围已落盘后更新。重连、首次连接及周期性对账均补查，实时事件和历史并发重复由平台 ID 与应用 messageId 两级去重。只能读取持久到本地的消息才发业务 accepted；结果也必须在发送方落盘后才报告已收到。历史保留不足、分页缺口或容量不足时报告消费不完整并停止宣称可靠接收，不能跳过游标继续运行。历史保留、断线补查及自动 ACK 后进程崩溃是 P0a 必验项，源码路径不是运行通过证据。

## 7. 信任与现有规则

按用户确认，第一期面向本人的可信 Agent 协作，不新增工具白名单、目录访问隔离、子代理权限传播或专门审批系统，也不将其作为自动接待前置关卡。主代理沿用现有用户规则、项目规则与宿主权限，判断是否直接执行、委派、拒绝或询问用户；远端消息不自动产生新的用户授权。

保留通信身份认证、会话与任务归属校验、来源标识及日志脱敏。对端设备身份绑定于 Relaycast 服务端记录的真实发送 Agent ID；信封内自报设备名或 sender 字段不能替代该绑定。同设备多个会话共享受信传输身份，消息来源会话由发送方扩展提供；首版不宣称对同设备会话做独立密码学隔离。node token 与 Agent token 不写普通日志，不将聊天 provider 凭据用作通信凭据。

查询意图和必要披露范围写入协作指引，由模型判断，不承诺强制只读、路径沙箱或防提示注入隔离。主会话及子代理仍可能拥有已有工具权限，这是明确接受的首版信任边界；不绕过宿主原有拒绝或审批，也不为此另建独立 SDK 工作者。

## 8. 生命周期与兼容

- “全局配置”指 getAgentDir() 下用户级 settings.json 的通信开关，不是即时跨进程控制。首版仅支持修改配置后，在各相关会话重载／重启生效；已运行会话保留原快照，未重载前不宣称已经关闭，新会话读取最新值。没有运行时一键全局启停接口。
- 本地路径以宿主 getAgentDir() 为根，沿用现有模型缓存的目录定位方式；通信密钥固定为 join(getAgentDir(), ".secrets", "relaycast.key")，不新增逐设备密钥路径配置，不用 HOME、工作目录或插件安装目录代替，不内嵌 token。状态与密钥分开保存。
- 共享传输以服务地址、工作区、设备身份和凭据引用的不可变配置快照为作用域；配置冲突时报告需重载，不能用新会话覆盖仍服务旧会话的连接或认证。
- 每个已加载主会话实例拥有任务路由、活动定时器与保活释放句柄；设备级连接、公告订阅、原始 inbox 和所有者锁由同进程传输实例按引用计数共享，不创建独立 Agent 或常驻外部服务。设备身份初始化用原子持久化协调。单会话退出只释放自身资源，不断开其他会话；通信全局未启用时不连接、扫描或公告。
- Pi Web 保活按确切会话注册，近期接待期间保持活跃。满 72 小时无消息更新后退出目录、停止新接单；尚有已接受任务时保留完成与回传所需运行状态，不取消任务或删除记录，妥善结束后释放通信保活。不干涉宿主因其他理由保持会话存活。
- 重载、会话替换和关闭时先停止该会话接单，持久记录在途状态及待发送 withdraw，再尽力发送并有界等待 flush，最后释放保活与共享传输引用；只有最后一个引用结束才关闭设备共享连接。flush 受单次控制消息发送超时约束，失败／崩溃不无限阻塞退出，由 90 秒心跳失联兜底，不承诺 withdraw 必达。跨 await 检查具体会话接待代次，不因一个会话退出终止其他会话连接。
- Pi CLI 依赖本身进程存活；Pi Web 保活注册表仅作运行时可选适配，不导入 Pi Web 内部模块，不影响其他宿主。
- 不提高原包最低 peer 来掩盖通信能力要求；不满足能力时关闭通信并显示原因，原入口继续工作。
- 第一期服务重启后需重新打开接待会话再连接。自动恢复指定会话属于后续宿主启动集成，不能只在会话扩展内实现自启动。
- 远端创建主会话属于后续宿主适配；Pi Web 有创建路由不代表通用 ExtensionAPI 已有任意设备创建能力，不把 localhost HTTP 或内部全局表作为默认公共接口。

## 9. 关键决策摘要

| 决策 | 口径 | 理由 |
| --- | --- | --- |
| D01 | 同包多入口，通信与模型 provider 解耦 | 独立启停、不增加发布维护单位 |
| D02 | 主会话接待、宿主子代理执行 | 保留用户已有上下文和工具治理 |
| D03 | 首版复用 Relaycast 原生消息桥，不新增网关；标准 A2A 延后 | 用户已确认降低维护成本；接受插件维护最小信封、目录视图与任务关联，不冒称后端原生或标准协议 |
| D04 | 不把会话文件、目录或端口当完整通信身份 | 避免多会话错投与重启身份漂移 |
| D05 | 接待保活与开机恢复分开 | 不许诺宿主尚未具备的常驻能力 |
| D06 | 首版复用模型判断与宿主已有规则，不新增权限隔离关卡 | 用户明确选择可信 Agent 协作，保留通信认证但不宣称强隔离 |

D01、D02、D03、D06 及个人可信网络的自动公告、3 天无消息退出有效目录规则为已确认方向。其余待审项不以文档存在视作部署或运行授权。
