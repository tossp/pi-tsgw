两者使用普通扩展预设与 tsgw/gpt-6-luna，已分别从 GET /api/sessions/{id} 回读结果，两份历史不含对方标记。各发起一次 prompt；获取结果接口纠正后仅继续回读，不重复推理。会话保留，不擅自删除。

源码入口：app/api/agent/new/route.ts 的 ensure_session、app/api/agent/[id]/route.ts、app/api/sessions/[id]/route.ts、lib/rpc-manager.ts。已发现的重要适配差异：

1. toolNames=[] 是 Chat only 预设，禁用全部扩展，连 tsgw 模型也不可选；不是“保留扩展但不开放工具”。恢复测试会话普通预设时宿主替换了最初空会话，必须使用返回的新 sessionId。最初空实例没有持久会话文件，没有发送模型请求。
2. Pi Web HTTP wrapper 不接受 CLI RPC 全部命令；get_available_models、get_messages 不可直接套用。使用 set_model 校验实际登记，使用会话历史接口读取消息。正式桥接必须依据实际宿主契约。
3. 测试中 set_auto_retry 被误判为会话局部操作，实际写入用户级 retry.enabled=false。发现后停止此类写入，从未重载的原主会话 get_state 读到原快照 autoRetryEnabled=true，以此为依据仅恢复该键为 true，保留 maxRetries=7。后续脚本已移除该调用。此副作用已向用户披露；不声称整个测试从未写配置。
