复核入口：本机 `/tmp/pi-communication-p0-native-ws-20261017.mjs`；本机直接执行，第二设备通过 SSH stdin 执行相同脚本、未创建远端文件。Node v24.20.0 与 v24.15.0 均通过。此前使用本机已有 ws 对照的独立合成探针另有 4 项断言通过；不将它当成已批准引入 ws。

**建议**：在已测的两个 Node 运行时优先使用原生 fetch／WebSocket 薄适配，避免直接采用 SDK 默认 query-token URL；暂不新增 Relaycast SDK 或 ws 运行时依赖。不把本次结果外推为全部 Node 版本支持，不提高原包最低 peer；不满足通信运行条件的宿主单独报告限制。

## 3. 通知持久化：正向证据可用，否定证明仍缺

专项子代理：`01a148a9-aa82-73f5-8fe5-8a21ff2dc5f7`。核对实际安装 SDK／agent-core 1.2.0，并执行真实 SessionManager 的临时合成写读探针，**18 项断言通过**；没有创建 AgentSession 或触发模型。该 18 项证据来自历史子代理报告，原临时脚本已清理，不能仅靠本仓库独立复现；正式宿主验收仍需补齐。

- 公共消息字段为 `custom_message.details.notificationId`，不是任意顶层 data。`pi.appendEntry()` 写的是不进入模型上下文的 custom 状态条目，不能冒充已投递通知。
- 公共 getEntries/getBranch 等可查询历史；旧分支存在不等于当前分支或当前上下文已包含通知。
- SessionManager 会先更新内存再写文件；custom-only 新会话可能只有内存记录。当前 ctx 内存查询、sendMessage 返回或 message_end 都不足以证明落盘。
- 已存在的会话文件经独立重新读取可证明消息已可从文件读回，仍不是 fsync／断电耐久证明；不能为了检查存在性而无条件调用可能创建文件的 open。
- 忙时 custom followUp 是内存队列；公开 hasPendingMessages 不一定包含这些 custom 排队消息。历史没有 notificationId 不能证明没有排队／没有投递。

安装包依据：dist/core/extensions/types.d.ts:1258–1272；dist/core/agent-session.js:752–761,1814–1857,2734–2742；dist/core/session-manager.js:791–819,947–960,1062–1116；agent-core/dist/agent.js:60–85,187–190。

**适配结论**：保留 v0.9 的 injection_unknown 降级。需要以实际可重读文件和原发起分支核验正向记录；只有内存或缺少否定证据时，不自动重复注入。未证明可靠的 busy 队列恢复或恰好一次，不标 P0 通知闭环通过。

## 4. 元数据、角色与活动时间：不能直接套列表字段

专项子代理：`01a148a9-aa78-73f5-8fe5-8a1e5c544c9c`。首次因 stream disconnected 中断后在原会话继续收尾；没有重复运行模型业务。合成 7 类 JSONL，经 SDK list/listAll 各返回 7 行，用于验证字段算法；临时合成数据已清理，原探针未归档；此处保留历史报告和源码依据，不宣称仓库内已提供该 7 类实验的独立复现入口。

- SessionManager.list/listAll 不启动模型，但会读取消息文本并返回 firstMessage/allMessagesText；不是保证底层不读正文的元数据 API。这些正文及衍生摘要不能直接进入通信公告。
- 列表字段为 modified，普通 user／assistant 更新计入，纯工具调用、空错误回复也可能计入；custom 协作消息不计入，空会话退到创建时间。它不符合本插件 lastMessageAt 定义。
- 当前运行会话可从公共 sessionManager 条目和生命周期事件计算活动；普通旧历史没有完整的人为输入／维护输出来源分类，不能假称全部可可靠复算。message_end 也不是统一的落盘确认。
- Pi Web 内置子代理标记为 type=custom、customType=pi-web:subagent、data.version=1 并含父会话字段；按宿主源码，该标记写在子会话 session_start 之前。可用公共 getEntries 读取，不导入内部模块；它仍是版本化宿主约定，不是 Pi 通用角色字段。
- session_start 才是可做角色筛选和登记的时点，扩展 factory 可能更早。普通 fork 的 parentSession 不能当子代理标记；未知子代理宿主仍按未知角色处理。
- 不订阅所有历史会话 SSE 来枚举：Pi Web events 路由可能启动相应会话，不是无副作用发现。

依据：SDK dist/core/session-manager.d.ts:163–181,408–414，session-manager.js:479–566,1449–1515；Pi Web lib/session-list-scanner.ts:191–267，subagents.ts:14,645–657，subagent-runtime.ts:442–494，rpc-manager.ts:567–597；SDK agent-session.js:751–773,2630–2652。

**范围提示**：原需求是不向远端公开正文，不能据此自动升级为“插件在本地绝不读取消息”。本地必要解析与公告披露应区分；但未加载历史会话的元数据如何公告、缺少可靠来源分类的旧历史如何处理，仍须明确实现口径，不能伪造其在线实例或保证完整历史目录。
