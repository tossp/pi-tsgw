# P0 原生通信探针

这些是无模型、无生产扩展注册的现场验证程序，不是已交付的通信插件，也不进入 npm 包。证据见 [P0 接口验证](../P0接口验证.md)。

## 文件与执行边界

- `worker.mjs`：控制程序以 P0_ALLOW_RUN=1 显式允许；没有该标记时，即使传入合法角色／run ID 也拒绝连接。使用宿主实际服务环境及公共 getAgentDir() 查找已授权设备密钥，以请求头连接原生 REST／WS，不执行消息内容。
- `run.py`：控制 claw 与 ts@hq-dev 的临时 Node 客户端；`--run` 会向正式 ts-agents 的两个专属 Agent 和 pi-sessions 发送合成信封，并断开／重连／主动退出临时探针进程。会生成新的测试 run，不是上次发送结果未知时的自动恢复方案；正常结束后探针进程退出。远端无临时源码文件，程序通过 SSH 的非敏感代码参数启动，密钥值不在 argv。
- `provision.py`：2026-10-17 已完成的一次性供应程序的源码留存。归档入口无条件退出，传入 --run 也不会供应；**不得因测试失败而解除保护重复供应**。供应失败或结果未知应先核对已创建对象与对应密钥文件，不自动覆盖、撤销或重建。管理 key 仅在 scnet 原机内存消费，设备 token 经被捕获管道定向写入已授权文件。

默认检查不会创建对象或调用业务接口：

```bash
python3 docs/communication/C00.执行计划/probes/run.py
python3 docs/communication/C00.执行计划/probes/provision.py
node --check docs/communication/C00.执行计划/probes/worker.mjs
```

用户再次明确授权真实消息验收后才执行：

```bash
python3 docs/communication/C00.执行计划/probes/run.py --run
```

已记录的 73 项检查来自 `/tmp` 原入口的一次真实执行，脱敏后的实际输出见 [传输检查输出](20261017-transport-result.json)；归档时增加默认不运行保护、将 worker 定位改为相邻文件，并显式校验子进程 stdin／stdout 管道；另补 worker 显式运行许可、只保留所需路径环境及损坏 inbox 受控停止检查；做了语法、默认不执行路径和主动 LSP 检查，**未再次发送消息**。权限、真实接口、SSH 入口、域名及运行时版本仍须按现场核验，不把本次结果外推到所有宿主。

## 数据与恢复边界

- 协作身份和 task 字段都是合成值；没有 AgentSession、主代理或子代理执行。`accepted/result` 在这里只验证 text 字段及传输关联，不是业务状态机已经实现。
- 两端临时 inbox 仅保存本 run 的合成文本和投递元数据，不含密钥、真实会话路径或聊天；位于各设备 `/tmp/pi-relay-p0-*`。程序不删除已有数据，不清理远端测试消息，正式设备身份和频道保留。
- ACK 窗口测试先确认服务端 delivery 为 acked、应用 inbox 中缺失，再以退出码 77 结束指定探针；重启探针复用其 inbox，从 REST 历史补回。未重启中央服务或 Pi Web，也未测试宿主真实通知队列恢复。
- 损坏／截断 inbox 受控拒绝启动，不自动清空或跳过坏行；可用 worker.mjs --check-inbox 从 stdin 做无网络合成检查。未实现一般 torn-write 修复，recover 只覆盖测试窗口最多 100 条，不是正式连续游标或完整分页恢复器。
- 生产保留的 P0 公告不含正式必需的实例／活动版本字段；正式协议解析必须拒绝缺字段公告，不把合成 p0-* 条目加入有效目录。
- 归档含非凭据环境定位信息，仅用于本批本地提交；对外推送前须另核对公开范围。.npmignore 排除不等于 Git 不发布这些文件。
- 不支持不经授权修改正式消费者、自动重试新的有副作用请求、重置主力会话或打印凭据。
