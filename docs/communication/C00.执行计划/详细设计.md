## 2. P0：消除实施阻塞

### P0a：原生消息桥与宿主接口

- 按实际影响选择验证入口：只读检查直接使用现有服务；已获授权的会话收发用新建真实测试会话，不向主力会话注入测试消息。只有会干扰现有工作的重启、断网等操作才另评估隔离或单独授权；隔离环境不是统一前置条件。凭据仅经正常认证机制在所属环境内消费，不回显。
- 核对原生 DM、text 完整 JSON 信封、data 辅助标签、Idempotency-Key、私信参与者／服务端 sender Agent ID 与历史分页；尚无 taskId 的确认丢失须可用 task_query.originalMessageId 找回原任务；原 request 网络重传用固定键，但不能指望平台幂等命中再次投递。平台发送回执不冒充 accepted。
- 核验 Agent token 换 node token、主动出站 WS、发现频道 join／历史／实时消息与设备身份绑定；频道及每设备 Agent 的一次性供应须先审批，不将 workspace key 下发到插件。
- 验证 SDK 自动 ACK 早于异步消费的崩溃窗口：重连时以私信会话历史补收，即使平台已 ACK 也不得丢业务消息；每个 DM conversationId 与发现频道分别保存独立连续游标，不能跨流推进；10.4.2 的会话列表无分页游标，不传 limit 才完整枚举参与会话；超本地容量标不完整。新发现流从可读历史起点建立基线。连续历史页落入持久 inbox 后才推进该流游标，验证分页方向、P/Q 交错消息及列表分页，发现缺口不得静默跳过。
- 核验宿主主／子角色、近期会话元数据、lastMessageAt 提取与变更跟踪；72 小时由客户端有效目录过滤，不要求后端 TTL／CAS 或物理删除。验证发现历史按 ownerEpoch／activityRevision 与独立 presenceRevision 重建，30 秒心跳、90 秒失联、平台时间及历史重放不续心跳；分页不完整时显示不完整而非不存在。
- 验证同进程多会话共享设备传输、引用计数和跨进程排他所有权；同设备身份冲突不抢占，不把 node/provider 仲裁当逻辑会话锁。
- 分别记录部署版本、客户端版本、实际消息样本与限制；expectedRoundId、期限和错误码必须在原生 text 路径完整保留。标准 A2A SDK、联邦入口及新增网关不属首版前置。
- 对 Relaycast 在授权范围内直接核验已部署端点；创建或删除远端对象、修改服务配置及重启均不在本轮接口读取授权内。
- 通过标准：双向仅主动出站可收发；应用 accepted、状态查询与结果关联可验证；断线补收、认证、错误及消费缺口真实可见。
- 核验本地通知 notificationId 能否保留并在原会话历史中查证、忙时队列持久性与可靠证明未投递的条件；sendMessage 返回及历史暂未出现均不能直接作为成功／失败证明，无可靠证据则采用 injection_unknown 显式降级，不自动再注入。
- 补验主／子代理角色标识、消息来源分类可复算性、子代理运行状态关联可用性；记录接口缺失时按 B00 报告限制，不宣称宿主保证任务关联。
- 验证退有效目录后，经原设备 Agent＋会话身份仍可向运行实例查询原记录／重放；会话回收后报告暂不可达，重新打开恢复访问，查询不重新公告也不续期。设备传输不擅自代替会话接单。
- 输出：原生桥接接口契约、一次性设备供应方案、实际缺口、依赖／许可证清单。使用已有 Node HTTP／WebSocket 与受控薄适配或引入 Relaycast SDK 的取舍须有具体依据，新增运行时依赖仍须审批，不提前假定包中已有 ws 或新 SDK。

首版不设置原 P0b 权限隔离关卡，不实现独立 policy 模块。模型沿用现有规则判断请求；来源标识、任务归属及宿主原有权限不被绕过，作为 P2/P3 的正常验证项，而不是新增强隔离前提。

## 4. 拟定配置与操作面

配置拟放 getAgentDir() 下 settings.json 的顶层 tsgwCommunication，与现有 tsgw 模型配置分开；初始化读取，不承诺项目合并与热加载。键名在实施审批前不冻结。首版近期窗口固定 72 小时，不提供配置项；enabled 是用户级持久配置，修改后各会话重载／重启生效，不提供即时跨会话或跨进程总开关。

首版心跳设计参数固定为 30 秒、失联阈值固定为 90 秒，不新增这两个配置项；实际环境按 P0a 验证，有变化先修订设计，不能混同于 72 小时窗口。控制消息 flush 使用有界发送超时，具体上限在实现审批前补齐。

建议配置内容：enabled（默认 false）、deviceId（默认自动生成并持久保存）、设备显示名（默认 hostname）、既有 Relaycast 地址、设备专属 Agent 身份、专用发现频道、队列容量、最大任务期限、时钟容差、去重保留期与结果保留期。首版不增加工具或目录权限配置。密钥固定由 join(getAgentDir(), ".secrets", "relaycast.key") 定位，沿用模型缓存由宿主 getAgentDir() 推导路径的方式；不新增逐设备密钥路径配置，不硬编码 home、用户名、插件安装目录或工作目录。普通配置不内嵌 token，通信状态与密钥分开；数值上限仍由 P0 补齐。不将聊天 provider 凭据或 workspace 管理 key 作为设备通信凭据，不在示例中写真实端点或密钥。

拟定操作如下；默认只提供查询意图，不提供任意远程命令执行接口：

| 操作 | 语义 |
| --- | --- |
| 会话列表 | 列出 3 天窗口内会话元数据，区分近期离线与当前在线／忙碌；不返回聊天正文 |
| 发起查询 | 指定规范会话身份、问题、范围与交付要求，先按原 messageId／originalMessageId 识别恢复操作，走原记录查询，不将其当新接单；原记录不可达时报告暂不可达，不能转成新请求。只有明确发起的新请求才检查目标近期与运行资格：已知实例存活但暂停返回 session_paused，无实例返回 target_unavailable，不排发送／执行队列；设备断网而无法收到错误时只报告目标不可达／接收未确认，不伪造远端错误回执。校验通过才持久记录消息并返回 messageId 及发送／未确认状态；收到 accepted，或经 originalMessageId 关联查询确认原请求已被接受并取得 taskId 后，才绑定对端 taskId；平台发送回执不构成已接单 |
| 查询任务 | 读取同一调用会话有权访问的状态、结果或待补充问题；已接受任务响应附当前实例、近期资格及可否续问，不唤醒模型或续期 |
| 补充输入 | 先处理已接受消息的幂等恢复；新消息必须携带 expectedRoundId，原子比较所回答轮次与等待态，检查近期资格、期限及当前目标实例后进入新 roundId，不延长 taskExpiresAt；退目录返回 session_paused，须本地继续对话后查询新实例再续问，不远程自动恢复 |
| 请求补充输入 | 执行侧提交 taskId、当前 roundId、问题、operationId、子代理及停止声明；先校验执行会话归属，再查持久键“执行会话身份＋taskId＋operationId”，同键同内容返回原接受事实和当前状态、不新发通知，异内容 conflict。新操作仅 working 且轮次、期限、近期资格、必要子代理停止均满足才原子进入等待；已等待时任何新 operationId 均优先 conflict（包括同时暂停），未等待的 working 任务暂停则 session_paused；不递增 roundId |
| 待办列表 | 主模型读取当前会话关联的入站任务，不依赖单个全局活动请求 |
| 提交结果 | 显式指定 taskId、roundId，声明关联子代理运行及停止状态；校验归属与终态，有宿主状态时交叉检查；已知必要子代理仍运行不接受正常 completed，但超时／失败可记 failed 并注明停止未确认；无可靠状态时标为模型声明未核实 |
| 通信状态 | 只读显示当前实例配置快照、连接、固定窗口、保活和重载限制；启停通过用户级配置加各实例重载完成，无逐会话名单 |

### 最小协作信封

协议标识拟定为 pi-tsgw-communication，version=1；完整 JSON 存在 DM／频道消息 text 中，data 仅作可选标签。接收先确认专用频道或私信参与者及服务端 Agent ID，再解析有界 JSON。平台消息 ID 仅用于收件箱，不能代替应用 messageId。

| kind | 必要关联及行为 |
| --- | --- |
| announce／presence／withdraw | 仅发现频道；设备／会话身份及该会话接待实例的 ownerEpoch、instanceId、activityRevision、presenceRevision、lastMessageAt、lastHeartbeatAt 和展示元数据；活动与在线状态独立合并，共享 WS 不变而单会话重开也换代，旧撤销不影响新实例或新活动 |
| request | 私信；messageId、from/to、contextId、目标 ownerEpoch／instanceId、固定 taskExpiresAt／replayUntil 和查询 payload；无在线目标不发新请求 |
| accepted | 私信；correlationId 指向原 request／input，返回接收方 taskId、当前 roundId、状态及 stateRevision；可靠记录后发送，不触发模型 |
| task_query／task_state | 私信；查询有独立 messageId／correlationId，选择 taskId 或原 originalMessageId 并绑定调用方会话；只读返回接收事实、任务状态、等待轮次和已保存问题／结果；附 originalRequestMessageId 便于恢复绑定。查询本身不触发推理，缺失的有效问题／结果按 B00 的逻辑通知键补齐本地队列；已接受任务另附当前 ownerEpoch／instanceId、activityRevision／presenceRevision、lastMessageAt／lastHeartbeatAt、近期资格及可否续问，路由信息不受 task stateRevision 不变阻挡且按自身版本合并，不唤醒模型；无接收记录不证明原消息永不抵达 |
| input_required | 私信；correlationId 指向开启当前轮的 request／input，另含 originalRequestMessageId、taskId／contextId、roundId、stateRevision 和问题 payload；对应执行侧已持久等待状态。发起侧按逻辑通知键持久排队并呈现；重发／查询补齐不重复唤醒，较旧问题不注入 |
| input | 私信；新 messageId、原 contextId／taskId、expectedRoundId、查询取得的当前目标 ownerEpoch／instanceId 与固定期限；去重优先，再原子比较等待轮次、实例与近期资格；旧实例返回 target_instance_mismatch，退目录返回 session_paused，不自动改投或激活 |
| result | 私信；taskId／roundId、originalRequestMessageId、状态版本 stateRevision、结果或失败说明；发送前落盘且终态不变。收件方原子保存载荷和 pending_injection，再回 received；原请求绑定未确认时先关联核实，本地通知恢复独立于远端是否重发 |
| received | 私信；对应 result 的 messageId，表示结果及本地通知队列已在发起端可靠保存，不表示模型已读取；没有新任务或客套回信 |
| error | 私信；对应请求 messageId 的受控错误，不触发推理；限 unknown_version、invalid_message、identity_mismatch、target_unavailable、expired、conflict、capacity、input_round_mismatch、target_instance_mismatch、session_paused、result_unavailable 等已定义错误 |

所有私信信封均含 protocol/version、kind、messageId、from/to；响应另含 correlationId，应用身份须与平台认证身份一致。request／input 的 replayUntil 不晚于固定任务期限；查询及终态结果按独立消息有效期与结果保留期校验，不因原任务期限结束就拒绝仍在保留期内的结果。所有信封有自己的 messageId；请求重放复用原 ID 和平台 Idempotency-Key，回执只确认其关联消息，不能替代任务状态。stateRevision 由执行侧 taskId 记录唯一递增，发起侧仅保存 remoteStateRevision，不将本地发送／未确认等投递状态混入。状态响应使用该持久 stateRevision，仅更高版本可推进／覆盖状态，避免较早 working 覆盖 completed，已确认终态也不被另一终态覆盖；同版本一致消息仍可完成查询、补齐尚未落盘的终态结果并重发 received，但不重复触发模型；同版本矛盾内容报告 conflict，不静默接受；终态后等待输入必须拒绝。超时只报告未确认，不制造远端失败事实。数值上限在实现审批前补齐，不把任意来源 JSON 注入模型。协议错误不响应错误本身，received／accepted 不互相确认，避免控制消息循环。

本地通知另存 pending_injection／injecting／injected／injection_unknown，与 task stateRevision、网络 received 分离。逻辑键为执行方身份＋taskId＋roundId＋kind＋stateRevision，附稳定 notificationId／原 messageId；每次注入前持久标记，notificationId 使用 custom_message.details；独立重读已存在文件、核验原发起分支记录后才标 injected，内存历史／事件不是落盘证明。pending 在重开后可继续；injecting 查到相同标记只补状态，证明未投递才重试，否则显式未确认、等待人工核对，不宣称恰好一次。重复网络 result 只合并既有通知、恢复 received，不重置本地投递状态；查询补齐问题／结果也复用相同键。通知保留期限及队列容量在实现审批前补齐，未确认项不得静默驱逐。

请求补充输入的 operationId 幂等记录与任务原子保存，含问题、轮次及声明（按结构化值而非 JSON 排版比较），采用下述恢复索引保留窗口；迟到重放返回原操作事实与当前任务状态，期限已到先转 failed，不复活旧等待或重发旧问题。

恢复索引在任务／轮次记录独立保存已认证调用方＋原 request／input messageId 的映射；非终态不得删除，终态至少保留到 max(taskExpiresAt＋时钟容差, resultRetainUntil)。短期去重表过期不影响非终态或结果保留期内查询；结果保留期过后索引仍在时返回 result_unavailable；原消息自身过期仍不得执行。

对发起查询等有副作用操作不配置自动新请求重试；允许的恢复为 B00 §6 经验证的有界同消息重放和无副作用的关联查询；查询可用独立 query ID，不创建新执行任务。发送前持久记录原始消息，确认后绑定 taskId；发送方恢复不重新生成请求。首版连接与目录刷新不等于模型健康检查。

### 独立保活探针的复核入口

下面是此前四项断言的参数化复核形式，仅验证源码中的注册、精确匹配、活跃状态及释放；不创建 AgentSession、不调用模型或网络。PI_WEB_SOURCE 指向单独检出的 Pi Web 源码，不是本项目目录。

```bash
PI_WEB_SOURCE=/path/to/pi-web node --experimental-strip-types --input-type=module <<'JS'
import assert from 'node:assert/strict';
import { pathToFileURL } from 'node:url';
const source = pathToFileURL(process.env.PI_WEB_SOURCE + '/lib/session-liveness.ts');
const { registerSessionLivenessProvider: register,
  hasActiveSessionLivenessProvider: has } = await import(source.href);
let active = true;
const release = register({ name: 'isolated-probe', sessionId: 'probe', isActive: () => active });
try {
  assert.equal(has({ sessionId: 'probe' }), true);
  assert.equal(has({ sessionId: 'other' }), false);
  active = false;
  assert.equal(has({ sessionId: 'probe' }), false);
  active = true;
  release(); release();
  assert.equal(has({ sessionId: 'probe' }), false);
} finally { release(); }
JS
```

Pi Web 原有 session-liveness.test.mjs 和 subagent-runtime.test.mjs 是后续完整验证入口；它们未因本探针通过而视作已运行。缺少开发依赖时应报告限制，不擅自安装或修改源码工作区。

## 8. 发布、回退与恢复

- 不迁移现有聊天、模型配置或历史会话；新能力默认关闭。
- 获授权发布时遵循项目 tag／Actions 流程；方案审批不自动授权发布。
- 停止接待先停止新请求，再记录未完成任务并释放连接与保活；禁用通信入口不应关闭其他能力。
- 版本回退不得删除本地任务记录；旧版不认识的新记录拒绝读取，不覆盖损坏数据；必要时人工恢复。
- 设备 Agent／发现频道的一次性供应、凭据轮换及任务记录清理均须各自授权；首版不部署新网关或替换旧服务，不能当作功能回退的隐含步骤。
