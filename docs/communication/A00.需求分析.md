# 通信能力：需求分析

## 背景与边界

用户在不同设备使用 Pi／Pi Web，不同项目和资料分布在不同设备。目标是在现有主会话之间发起查询、响应查询，并在必要时为独立议题创建会话，而不是通过 SSH 远程操作另一台设备。

本专题是待审方案，不是已实现能力。术语见 [名词解释](000.名词解释.md)，架构见 [规划设计](B00.规划设计.md)，实施与验收入口见 [执行计划](C00.执行计划/详细设计.md)，状态只维护于 [TODO](000.TODO.md)。

## 用户已确认的方向

- 通信能力集成在 pi-tsgw 同一包，不增加独立发布包。
- 复用项目目录、会话 ID、名称等现有会话信息，不另造会话管理体系。
- 优先服务资料查询与项目联动；已有主代理能够委派宿主子代理并回收结果。
- 通过中央服务跨设备联系，不以设备间 SSH 作为通信方案。
- 首版复用已部署 Relaycast 的原生消息接口，由同包扩展桥接 Pi 会话；不新增中央网关，不把标准 A2A 兼容作为首版交付前提。标准 A2A 留作后续可选适配，不能把本插件消息称为标准协议。
- 应考虑会话创建；已有会话通信与独立议题创建不能混为一件事。
- 首版不增加专门的工具、目录或子代理权限隔离，由主代理沿用现有规则判断；认证及宿主已有权限不取消。
- 个人可信网络不另设设备、项目或逐会话接待白名单；启用通信后自动登记近期会话。最近消息更新满 3 天（72 小时）退出目录；退出后的远端新请求或续问不得自动激活，须用户在本地继续对话恢复近期资格。已有执行收尾仍按真实消息口径处理；不删除历史或公开聊天正文。

## 推荐交付分期

- 第一期：现有主会话间的双向查询、子代理结果回传、接待保活与失败可见性。
- 后续期：在指定设备和目录显式创建主会话、服务重启后的自动恢复接待。
- 分期是本方案建议，不表示会话创建需求被取消；最终范围以审阅结论为准。

## 使用场景

1. 会话 A 请另一设备的会话 B 查阅当地文件；B 按任务需要直接回答或委派子代理。
2. B 向 A 反向发起查询；同一请求的答复、失败与追问不与并行请求混淆。
3. 用户关闭 B 的浏览器页面后，已启用接待的 B 仍能处理获准请求。
4. 用户指定目标设备、目录及议题，创建可继续讨论的新主会话；不得切走已有会话。
5. 接收方正忙、离线或服务重启时，发送方能知道真实状态，而不是误认为已完成。

## 功能需求与验收口径

| ID | 需求 | 验收场景 |
| --- | --- | --- |
| R01 | 同包独立通信入口，任何模型 provider 下可用 | 单独禁用通信入口后，原模型、上传及提示词功能保持可用 |
| R02 | 自动公告最近 3 天更新的会话，按设备标识与会话 ID 精确寻址 | 72 小时边界退出目录，暂停期间远端新请求或续问不激活，本地继续对话后重新加入；心跳不续期；近期离线与在线可接收分开显示；自动设备身份重启稳定，同目录多会话不串线；不公开聊天正文 |
| R03 | 双向查询与结果关联 | A 查询 B、B 查询 A；并行请求各自得到对应结果、来源位置与未确认项；缺少参数时可显式请求补充输入并关联原轮次 |
| R04 | 由主代理决定是否委派宿主子代理 | 已启用子代理时，远端查询可触发主代理委派、回收并回复；不要求每个请求都启动子代理 |
| R05 | 忙碌时不抢占当前任务 | 请求排队，原工具调用不被打断；空闲后处理正确请求；有界队列满时明确拒绝 |
| R06 | 近期在线会话不依赖浏览器持续打开 | 关闭页面后跨过普通空闲回收周期仍可查询；满 72 小时无消息更新退出目录、停止新接单，已接任务妥善结束后重新检查资格，仍过期才释放通信保活；已接任务收尾产生合格消息则重新加入；新远端续问不绕过暂停，须本地继续对话恢复；不删除历史 |
| R07 | 显式创建议题主会话，后续期 | 指定设备、目录、名称及初始任务，返回新会话 ID；当前会话不被替换；无宿主能力时明确不支持 |
| R08 | 真实区分接收、执行、完成及失败 | 服务器接受不冒充任务完成；不能确定是否执行时标记不确定，不自动重复执行 |
| R09 | 在记录端点可达及声明的保留窗口内，重连可查结果且不重复执行 | 同请求重发不生成第二任务，异内容冲突拒绝；退目录不删除记录，有实例时可查询；实例回收／关闭后暂不可达，重新打开原会话恢复记录访问，不冒充记录过期或不存在；进程中断不虚报仍在执行；已保存结果或等待问题的会话通知有独立恢复状态，问题通知丢失可经查询补齐且不重复唤醒，无法确认是否注入时显式提示，不静默丢失或重跑远端任务 |
| R10 | 重启恢复边界可见 | 第一期重启后需重新打开接待会话；未过近期窗口可查询新实例后续问，已过窗口须本地继续对话，任务期限届满不得续问；中断任务不自动续跑，后续期另验自动接待 |

## 非功能需求与验收口径

| ID | 约束 | 验收场景 |
| --- | --- | --- |
| N01 | 由主代理沿用现有规则判断请求，不新增权限隔离层 | 来源标识与非授权提示正确进入会话；宿主已有权限与审批不被绕过；不宣称模型判断构成强隔离或只读沙箱 |
| N02 | 最小披露与认证隔离 | 不自动传聊天历史、会话文件内容或密钥；读权限不等于允许远端获得全部文件；未认证请求不能唤醒模型 |
| N03 | 有界资源与循环控制 | 限制任务数、消息体、返回体、超时与有效期；结果消息不自动变成新的任务 |
| N04 | 不破坏宿主与旧功能 | 旧宿主缺能力时仅禁用通信，保持原包最低 peer 与现有能力；无 UI 依赖 |
| N05 | 复用既有中央消息服务，消息兼容有证据 | 首版通过 Relaycast 原生接口双向主动出站，不依赖设备公网入站、设备间 SSH 或新增网关；认证、结构化消息、重连与结果回传分别验证，不冒称标准 A2A 兼容 |

## 非目标

- 不建立新的设备总管 Agent、独立 SDK 工作者池或完整项目管理系统。
- 不自动登记所有历史会话，不让子代理默认成为跨设备公开端点。
- 不自动广播项目频道、同步整段记忆、共享文件系统或代替 Git 合并。
- 不承诺跨设备恰好一次执行、不间断运行或所有历史任务自动恢复。
- 首版不实现标准 A2A 端点、协议版本转换、流式任务服务或新中央网关；只保留完成本人的联动查询所需的协作约定。
- 不在本次规划中修改、替换或下线现有中央服务；不安装第三方插件或改变主力会话。
- OpenCode 可作为后续互操作对象，不作为 Pi 第一期验收的替代项。

## 待审取舍

1. 是否接受第一期不包含远端创建主会话及服务重启自动接待。
2. 原“标准 A2A 优先”的路线已按用户确认改为 Relaycast 原生消息桥；本地任务关联和恢复由插件负责，不因此宣称后端已有任务服务。具体原生接口、端点供应方式与依赖仍按 B00／C00 验证，不把路线确认扩大为实现、部署或凭据分发授权。
3. 自动公告按已确认的 3 天窗口执行；中央服务能否同步近期元数据及真实在线状态须经验证，不把发现历史会话视为已经能够自动启动该会话。
