# 聊天模型可用性测试

以一次最小真实任务验证指定模型能否回复及完成工具往返，不做性能榜单、全档位扫描或自动故障转移。测试范围以用户指定的型号和用途为准。

## 确定模型和档位

- 上下文已知可用型号及支持的思考档位时，直接测试，**不必查询目录**。
- 信息不足时，才通过 `codemode` 的内置全局对象 `models` 查询宿主目录；它不是独立工具，不需要用 `searchTools()` 查找。
- 不调用 `tsgw_refresh_models`，也不把目录刷新、重载或修改配置作为测试前置步骤或失败补救。

按需查询示例：将下方 JavaScript 交给 `codemode` 执行。仅查询 tsgw 时可将调用改为 `models.getAvailableOfType("chat", "tsgw")`；知道目标型号时，在输出前筛选即可。

```js
const entries = await models.getAvailableOfType("chat");
text(entries.map(model => ({
  provider: model.provider,
  id: model.id,
  reasoning: model.reasoning,
  thinkingLevelMap: model.thinkingLevelMap
})));
```

这里只输出选择所需字段，不打印完整目录项中的端点或其他配置。目录表示宿主已登记且有可用认证，不证明端点或型号的真实调用成功；查询不到也不能据此断言远端模型不可用。

`reasoning: false` 时使用 `off`；`thinkingLevelMap` 中的 `null` 表示不支持该档位。缺失项不能直接按“支持所有档位”处理：Pi 1.2 对普通档位采用宿主默认规则，`xhigh`、`max` 需要显式映射。不要凭同系列其他型号推断支持情况，也不要为验证一次可用性遍历所有档位。

## 执行最小真实任务

由主模型**直接调用 `Agent`**，显式填写 `model: "provider/modelId:level"`，不交给自动选型，也不把 `Agent` 包进 codemode。调用及后台结果处理遵循[子代理派遣技能](../tsgw-delegate-model-selection/SKILL.md)。

给子代理的任务保持最小，例如：

> 这是一次模型可用性测试。请实际调用一次已有工具：使用 bash 执行 `printf 'MODEL_TOOL_OK\n'`，再报告工具实际输出并简短回复。不要修改文件、读取凭据、请求外部服务或派遣其他子代理。工具缺失或调用失败就直接说明失败，不改用其他测试路径。

使用实际可用且无副作用的工具；已有明确测试任务时沿用该任务，不额外扩展范围。只有收到真实工具结果及后续模型回复，才能认定工具往返通过；子代理启动成功或口头声称调用不算通过。

## 判断和报告

- 分别报告文本回复、工具往返是否通过，并列出实际使用的型号和思考档位；宿主若报告了不同的实际档位，应明确说明，不算原指定组合通过。
- 失败、取消或超时就报告实际阶段和可公开的错误，不主动刷新目录、重试、换档位或换模型。用户另行指定下一次测试时再执行。
- 未创建子代理、仍在执行或结果未知时如实说明，不把它们写成模型已通过或端点已被证明不可用。
- 一次通过只证明该型号、档位在本次最小任务中可用，不推广为全部模态、长期稳定性或复杂工程能力已验收。
- 验证候选模型不等于已经切换主会话或修改默认配置；切换按用户授权另行执行。
