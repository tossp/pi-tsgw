# ts_gitlab 使用

## 实例与入口

- 本技能适用于砼砼 GitLab 实例 `code.tossp.com`，优先通过宿主已连接的 `ts_gitlab` MCP 操作，不与 GitHub 或其他 GitLab 实例混淆。
- 通过 `codemode` 的工具发现能力查找实际可用的工具，阅读声明后调用，不猜测工具名或参数。认证与权限沿用宿主，不另建凭据或修改 MCP 配置。
- 操作前核对目标项目及分支、MR 或 Issue；写操作遵守当前任务授权，读取权限不代表写入、合并、发布或删除授权。

## 新建仓库的默认位置

- 在该实例新建仓库时，优先使用 `av8d` 命名空间；用户明确指定其他命名空间时，以用户指定为准。
- 创建前核对 `av8d` 对应的实际命名空间及创建权限，不猜测 namespace ID。不可用时说明阻塞，不擅自改到个人或其他命名空间。此默认位置约定不代表已获创建仓库的授权。

## MCP 未覆盖功能的补充路径

- 当 `ts_gitlab` MCP 未提供所需功能时，在用户明确授权对应操作的前提下，可以使用该 MCP 现有授权文件中的认证信息，直接调用同一实例的 API；仓库删除属于此类操作，其他缺失功能同样适用。此路径不是对未授权操作的通用许可。
- 先核对当前工具能力与目标对象，明确授权覆盖的动作、范围及数量；批量或删除等高风险操作须以用户确认的目标清单为准，不擅自扩大范围。已有明确授权后不逐项重复询问。
- 按宿主实际授权文件位置与格式取用所需认证信息，不猜测路径、不遍历无关凭据，不另建认证存储，不修改 MCP 配置或授权文件。凭据仅用于本次获授权请求，不写入仓库、脚本、临时正文或日志，不输出原始授权文件、令牌及认证头。
- 仅向已核实的 `code.tossp.com` 实例发送认证信息，不向其他主机或跨源重定向转发；按实际认证方式调用，不将“功能未提供”与认证失败、权限拒绝或被禁用混为一谈，不借此绕过宿主或服务端权限限制。
- 操作后只读核验实际状态，区分已受理、计划删除与已完成等结果；请求结果不明时先查询，不盲目重复写入或删除。执行前若缺少必要权限或无法安全取用现有认证，应报告阻塞，不擅自登录、刷新凭据或更改权限。

## 远程仓库地址使用 SSH

- 提供该实例的 Git 远程仓库地址，或编写 clone、remote、fetch、push 相关示例时，统一使用 SSH 地址，不使用 HTTPS Git 地址。
- 优先采用项目详情返回的 `ssh_url_to_repo` 原值；保留实际 SSH 用户、主机、端口及完整命名空间，不凭网页地址猜测 SSH 连接参数。地址未核实时明确说明，示例不得冒充真实项目。
- 以下仅为格式示例，`GROUP/SUBGROUP/REPO` 为占位路径，实际以项目返回值为准：

  ```text
  git@code.tossp.com:GROUP/SUBGROUP/REPO.git
  ```

- 网页、MR、Issue 与 API 地址仍使用对应的 HTTPS URL；SSH 要求仅针对 Git 远程仓库地址，不改写对象链接或 MCP 连接地址。
- 此约定不授权自动修改已有 Git remote、SSH 配置或密钥；需要修改时按当前任务授权处理。
