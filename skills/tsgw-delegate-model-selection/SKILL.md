# 子代理编排与模型选型

当本技能存在时，应更倾向于把适合委派的任务编排为子代理背景执行，并尽量遵循本技能的模型与思考深度定义。具体编排由模型根据任务自行判断。

## 工程任务选型补充

代码修改、缺陷修复、补测试等常规工程任务，优先考虑 `deepseek-flash` / `high`；复杂实现使用 `max`。GLM 5.3 / Flash 仍是工程候选，结合套餐、速度与任务匹配选择，不设固定派遣路线。MiniMax、Luna 保留步骤明确的轻量执行分工。

复杂任务选择 `gpt-6.1-sol` 时优先 `high`；仅在任务确需更深推理时考虑 `xhigh` / `max`，不把提高档位当作必然提升。通用工程的 `medium` 仍保留，Astra 与 Kimi 的审阅分工遵循下文。

依据与适用范围：

- [DeepSeek 官方更新日志](https://api-docs.deepseek.com/updates/)（2026-10-17）确认官方 API 的 `deepseek-flash` 已升级为 V4.1 Flash-1017，并报告 DeepSWE v1.1 为 77.0%；该评测使用 Mini-SWE-V2，不是 Pi 子代理实测。
- 用户提供的 DeepSWE v1.1 通过率／每任务费用图用于工程选型参考，与上表 AA 综合能力评分分开，不混用分数，也不将某个代码评测推广为设计审阅能力排名。
- 官方 API 的别名更新不证明网关已经同步；当前未独立确认网关的具体后端版本，不将 77.0% 当作网关实测成绩，不新增猜测的模型 ID。选型模型直接参考本表及这些限制，无需自行查榜或探测版本。
- 图中每任务费用受评测框架、token 用量、定价及汇率影响，不等于本表 token 单价或用户网关实际扣费，也不保证本地任务的通过率与耗时。

## 必要边界

- **MiniMax-M3** 只承担步骤明确的小任务。参考使用 Pi 的 high；非 off 档位均映射为 adaptive，不代表不同能力档。adaptive 不是 Pi 档位，此映射不适用于 M3.1 Flash Preview。
- **deepseek-flash** 常规工程默认 high，复杂实现使用 max；这是选型指导，不自动切换模型、修改用户启用配置或触发付费探测。
- **Astra 审阅档位**：架构设计、正式设计文档的独立审阅与最终复核，默认使用 `gpt-6-astra` / `max`，不因材料篇幅短或范围明确而自动降档。局部检查、定向复审可按范围降低档位。
- **Kimi** 不承担长程执行；双模型复核固定为 **Kimi＋Astra**，独立审查同一份材料。Kimi 使用 kimi-k3 / high，Astra 遵循上述审阅档位规则；其他任务的深度按任务选择。
- 不可用的模型或档位如实说明。

宿主支持 `Agent.model = provider/modelId:level` 时，例如 `tsgw/MiniMax-M3:high`、`tsgw/glm-5.3:max`；其他宿主使用其实际格式。
