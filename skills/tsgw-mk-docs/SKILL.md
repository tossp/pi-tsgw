# 设计文档制作与进度管理

## 使用边界

- 本技能是独立的中文文档治理规则与静态参考资源，不包含运行时代码，不依赖审阅插件。
- 仅复制、收纳、打包、审计或维护本技能时，不启动项目文档规划、不创建项目设计文档。
- 资源路径相对于当前文件；参考资料中的链接相对于各自文件。来源与完整资源清单见 [来源与适配说明](SOURCE.md)。
- 不假定任何宿主专属命令、固定工具名或已安装插件可用；需要工具时以当前会话现场核验为准，不擅自安装、启用或修改配置。

## 适用范围

- 用户需要创建、迁移、验证或维护项目设计文档骨架。
- 目标是把设计信息收敛到 `000.*`、`A00/B00/C00` 主文档及其后续工作包中。
- 若项目 `AGENTS.md` 与本技能冲突，以项目 `AGENTS.md` 的项目事实、路径、例外、验证入口为准；若冲突涉及通用规范，先暴露冲突并澄清。

## 标准骨架

- `000.名词解释.md`
- `000.TODO.md`
- `A00.需求分析.md`
- `B00.规划设计.md`
- `C00.执行计划/详细设计.md`

## 推荐阅读顺序

1. 先读项目适用的 `AGENTS.md` 等规则和现有文档路径；项目指定的正式文档体系优先，不强制另建标准骨架。
2. 拿不准内容归属时，先读 [跨文档职责边界](references/design-doc-boundaries.md)。
3. 再按目标文档进入对应 `overview.md`、`modules.md`、`checklist.md`。
4. 状态与证据指针统一回写 `000.TODO.md` 或项目指定的状态记录。

## 迁移授权门槛

- 先完成只读盘点，按术语、需求、设计、执行、状态分类，完整列出每个源文件及其段落或章节、目标文件及目标位置、保留或调整方式。
- 必须在任何迁移写入前展示全部清单，包括新增、覆盖、改写、删除、重命名和引用修正，不以样例或部分清单代替。
- 等待用户针对完整清单明确授权后才写入；清单有实质变化时先补充说明并重新确认，未授权时仅提供分析。
- 用户授权本地技能收纳或打包，不等于授权迁移项目文档；本技能也不授予超出用户任务范围的写入权限。

## 正式文档审阅与授权边界

- 项目 `AGENTS.md` 的目录与例外规则始终优先，不要求项目引入 `000/A00/B00/C00` 骨架。
- 优先审阅已有正式文档：需求审阅对应 A 层，设计审阅对应 B 层，执行审批对应 C 层；采用其他目录体系的项目使用其职责对应的正式文档。
- 优先复用正式执行计划，在其中提供本次范围的实施清单与验证入口，不另建 `PLAN.md` 或 `plans/` 作为第二份权威计划；审阅要求与正式文档结构冲突时，先说明差异并确认适配方式。
- 审阅前确认文档职责、版本、操作范围和验收口径，检查需求、设计与执行计划是否一致。
- 收到审阅反馈后，按需求、设计、实现或状态职责回写对应正式文档；涉及范围或授权变化时先确认。审阅历史和归档副本不能替代正式来源。
- 修订后检查跨文档一致性，说明变化并按需复审，不把旧版批准沿用到实质变更后的文档。
- 普通批注不等于执行审批；需要执行时取得明确授权，并在受审文档中列明修改对象、范围、验证标准及必要的回滚边界。
- 批准只授权受审版本明确列出的操作，不自动包含发布、部署、删除、凭据或权限调整等未列出或要求单独确认的动作。被退回或发生实质范围变更时，先修订并重新确认，不执行旧版计划。
- 获授权后依据受审版本推进，继续维护正式计划、状态记录和验证证据；新增需求或架构变化先回到对应文档补齐决策，执行进度与验收证据回写 `000.TODO.md` 或项目指定的状态记录，只有验证通过才标记完成。
- 始终遵守只读规划、项目安全规则与授权边界，不以工具可调用作为扩大授权的依据；遇到冲突时暂停受影响的操作，说明冲突并确认处理方式。

## 执行要求

- 文档写作应使用符合中文正规文献或软件工程专业规范的书面用语。
- 避免口语化表达、内部黑话、语义含混的缩略说法，以及无必要的中英混杂表述。
- 同一概念在全套文档中保持术语和称谓一致。
- 必须使用外文术语时，给出规范中文名，或明确约定主叫法。
