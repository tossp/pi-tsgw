# B00.规划设计.md 总览

## 职责

- 回答系统怎么分、模块怎么协作、协议 / 边界 / 数据流怎么定。
- 把 `A00.需求分析.md` 的需求和约束映射成可实施的系统边界。
- 记录关键设计决策、取舍理由和质量属性落实方式。

## 边界

- 不写代码改动清单、逐文件实施计划、迁移任务清单。
- 不写 CI job 细节、发布步骤、联调流水账或实施状态。
- 不用 TODO 状态替代设计正文，也不把临时实现技巧上升为架构原则。

## 写法口径

- 小变更下，B 文档是条件性设计文档；当现有边界足够稳定时，可只补最小决策记录。
- 轻量写法可参考 OpenSpec design 的条件性设计思想：只写当前变更真正需要澄清的结构与决策。
- 中大型项目可参考 arc42、IEEE 1016 和常见 GB 概要设计口径，但按项目风险裁剪章节。
- 模块裁剪见 [模块裁剪](modules.md)，交付前复核见 [复核清单](checklist.md)。

## 最小结论

- 至少说明上下文、关键边界、核心决策以及它们如何承接 `A00` 需求。
