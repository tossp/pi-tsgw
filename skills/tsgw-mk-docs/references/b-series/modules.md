# B00.规划设计.md 模块裁剪

## 必选最小模块

- 小变更且现有架构边界稳定时，`B00` 可以省略为独立文件。
- 若需要写 `B00`，最小只保留 `Context` 和 `Decisions`：
- `Context`：当前系统边界、相关参与方、外部依赖、已有约束。
- `Decisions`：当前必须冻结的模块划分、接口边界、数据口径或策略取舍。

## 常用可选模块

- `Goals / Non-Goals`：本轮设计要解决什么，不解决什么。
- `Risks / Trade-offs`：风险、代价、质量属性冲突和取舍。
- `Alternatives`：备选方案、拒绝原因、适用前提。
- 模块职责：谁负责什么，也写清楚不负责什么。
- 接口边界：输入输出、所有权、版本口径、失败语义。
- 数据模型口径：关键实体、字段含义、一致性和生命周期。

## 中大型项目模块

- arc42 / 概要设计式上下文与范围。
- 约束与驱动因素。
- 构建块视图：模块分层、职责、依赖。
- 运行时视图：关键场景、时序、交互链路。
- 部署视图：环境、节点、边界、外部系统。
- 横切概念：安全、可观测性、配置、错误处理、兼容策略。
- 质量需求映射：把性能、安全、可靠性等映射到设计决策。
- 设计决策、风险与技术债。

## 何时必须写 B

- 变更跨多个切面或多个模块边界。
- 引入新架构、新外部依赖或新的部署/交互边界。
- 数据模型、协议口径或接口契约发生变化。
- 安全、性能、迁移复杂度显著提高。
- 现有实现存在歧义，`C00` 无法在不猜测架构的前提下落地。
