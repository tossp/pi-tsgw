# A00.需求分析.md 总览

## 职责

- 回答为什么做、要做什么、做到什么算完成。
- 定义问题空间、范围边界、验收口径和稳定需求输入。
- 作为 `B00.规划设计.md` 与 `C00.执行计划/详细设计.md` 的上游依据。

## 边界

- 不写架构、模块拆分、接口协议细节、数据流和系统分层。
- 不写代码落点、目录映射、脚本命令、迁移步骤和实施状态。
- 不用任务状态或 TODO 勾选替代需求正文。

## 写法口径

- 轻量写法可参考 OpenSpec 的 proposal / spec 思路：只保留当前变更真正需要的需求模块。
- 中大型或合规项目可参考 IEEE 830 / ISO 29148 的 SRS 组织方式，但只采纳需要的章节，不复制整套模板。
- 模块裁剪见 [模块裁剪](modules.md)，交付前复核见 [复核清单](checklist.md)。

## 最小结论

- 至少回答背景、目标范围、稳定需求 ID、验收标准。
- 每条需求都应能被 `B00` 设计映射和 `C00` 验证入口追踪。
