# C00.执行计划/详细设计.md 模块裁剪

## 必选最小模块

- 分组任务：按实现闭环拆成可执行的小组，而不是只列主题。
- 可验证步骤：每组任务都要有完成判定和验证入口。
- 依赖顺序：说明先做什么、后做什么、哪些前提必须满足。
- 执行入口：给出从哪里开始改、从哪里开始测。

## 常用可选模块

- 代码落点：目录、文件、函数、模块、配置键。
- 配置 / 脚本 / 命令：需要修改什么，如何执行。
- 测试入口：单测、集成、联调、验收入口与前置环境。
- 回滚 / 迁移：数据、配置、兼容开关、发布回退路径。
- 验收映射：把 `A00` 验收标准和 `B00` 边界映射到具体验证动作。

## 中大型项目模块

- 详细设计式模块说明：职责、边界、依赖。
- 输入 / 输出：参数、事件、报文、状态变更。
- 算法 / 流程：关键流程、状态机、异常处理。
- 接口：内部接口、外部 API、调用约束。
- 存储：表、索引、缓存、文件、生命周期。
- 错误日志：错误码、告警、日志、可观测性入口。
- API 详细设计：字段、语义、兼容、版本演进。
- 数据库物理设计：表结构、迁移顺序、回滚策略。
- 测试计划：覆盖面、数据准备、环境、验收方式。

## 执行原则

- 任务条目应尽量控制在一次会话或一轮内可完成。
- 未完成时先回写结果、失败原因和偏离点，再调整设计文档或 `000.TODO.md`，不要让计划与现实脱节。
