## 维护原则

1. 完整阅读技能、项目约束和目标代码，区分官方阅读要点与本技能强制约定。
2. 需要确认版本能力时，核对项目实际 Go 工具链、官方文档与最小测试；不猜测新 API 或最低版本。无网络或工具受限时明确报告未验证内容。
3. 使用宿主实际提供的工具，不依赖特定 OpenCode 抓取入口；不因维护技能而擅自安装工具或升级项目依赖。
4. 参考保持中文、简明，每份不超过 500 行。不要用许可不明的官方长文副本替换阅读要点。
5. 修改后检查技能声明、相对链接与规则完整性，不将静态检查说成实际代码或宿主验证。

## 强制约定保留清单

- 自产 JSON 默认 PascalCase；外部解析例外仅限不可控来源的输入。
- 根据零值省略时优先 `omitzero`，包括自定义 `IsZero() bool`；明确需要空值语义时才用 `omitempty`。
- 无需重命名则不重命名；只省略零值用 `json:",omitzero"`，显式命名并省略零值用 `json:"FieldName,omitzero"`；两者均不需要则不加标签。
- 同一 struct 不混用新旧命名风格；真实功能或修复触及所属 struct 时，同次迁移相关旧标签。
- 不创建仅统一标签的迁移 PR，不扩大成无关全文件或全仓改写。
- 不以跟随官方为由删除或降级这些最佳实践；遇到明确公共协议、兼容性或工具链冲突，先暴露影响并确认，不擅自破坏协议或虚报合规。
