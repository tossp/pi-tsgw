# Go 惯用法：中文阅读入口与要点

本文自主组织本地已有资料中的要点，供离线阅读与定位问题使用；不是官方全文、逐字译本或完整规范，也不是本轮核验的最新版。

官方入口：<https://go.dev/doc/effective_go>。

本地源资料提醒：Effective Go 起源较早，不能单独覆盖构建、测试、modules 等后续生态主题。本轮不补写未经核验的新版本知识。JSON PascalCase、omitzero 优先及随真实变更迁移属于 `../SKILL.md` 的本技能约定，不是本文所链接官方指南的统一要求。

## 格式、注释和名称

- 使用 `gofmt` 决定缩进和对齐，不靠人工维护格式；控制结构不套 C 风格括号。
- Go 没有硬性行长上限；按语义与可读性断行。
- 声明的文档注释应紧邻声明；导出符号的注释以其名称开头。
- 包名简短、小写，使用时避免重复包名语义；普通多词标识符使用 MixedCaps 或 mixedCaps，不用下划线。
- getter 通常直接以属性名命名，不机械添加 `Get`；单方法接口可按行为命名，例如 `Reader`。

## 控制流与函数

- `if`、`switch` 可带初始化语句，使临时变量贴近使用位置。
- `for` 可表达条件循环和无限循环；遍历集合时按需求使用 `range`。
- `switch` 分支默认不会自动贯穿；无表达式时可表达条件分支。
- 用多返回值表达结果及错误，不把失败塞进正常结果的特殊数值中。
- 命名返回值应帮助理解语义，避免造成重复说明；较长函数使用显式返回值。
- 成功获取资源后安排 `defer` 清理；延迟调用按后进先出执行。清理中有错误也应按项目要求处理，不能拿示例当作忽略错误的许可。

## 数据、初始化和方法

- `new(T)` 返回指向 T 零值的指针；`make` 用于初始化 slice、map、channel，并返回该类型的值。
- 数组是值，长度属于类型；slice 引用底层数组，修改和复制时留意共享关系。
- map 用于键到值的映射，按访问需求选择结构。
- 常量在编译期确定；变量初始化可以执行运行期表达式。`init` 在包变量初始化后执行。
- 按方法是否修改状态、是否允许复制等需求选择接收者形式，不能仅凭语法习惯选择。

## 接口、组合和并发

- 接口描述行为，围绕真实调用需求保持精简；必要时用类型断言或类型 switch 区分接口中的具体值。
- 嵌入用于组合实现或行为，不把它等同于传统继承。
- 空白标识符表示有意舍弃值，不得借此无声丢弃应检查的错误。
- 用 goroutine 表达并发执行，用 channel 通信协作；通过通信共享内存。
- 明确任务如何完成、何时停止、发送和接收能否阻塞，避免把并发语法等同于正确的并发设计。

## 错误

- 普通失败以额外的 `error` 返回值报告，调用者必须检查并处理。
- 不用 `panic` 替代普通错误返回。`panic` 会沿当前 goroutine 的调用栈展开并执行延迟调用；`recover` 的存在不是吞掉普通错误的理由。
