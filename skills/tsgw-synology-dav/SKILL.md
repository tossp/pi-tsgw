# 群晖日历与联系人

涉及用户日程、联系人或空闲时间时，优先查询真实数据，不凭记忆猜测。不因工具可发现就认为已经配置或验收，也不自动修改配置、登录或迁移旧凭据。

## 原生只读入口

- 先按需 `describeNamespace("tsgw_dav")`，再用 `describeTool()` 查看本次所需参数。`accounts` 只列账户 ID／已配置时区；`collections` 必须显式传 `account` 与 `kind`（calendar 或 addressbook），不默认取首个集合或合并账户。
- 原生工具为 `accounts`、`collections` 及 `event_list/get`、`todo_list/get`、`journal_list/get`、`contact_list/get`，均带 `tsgw_dav_` 前缀；当前没有联系人多字段搜索和创建／修改／删除。不要构造不存在的工具名，也不把读取失败作为自动切换旧 MCP 的理由。
- 遇到 `CONFIG_REQUIRED`／`CONFIG_INVALID`，指导在宿主用户目录 `tsgw.json` 的 `dav` 组按 ID 配置 `url`、`user`、`password` 与可选 `timeZone`，权限 0600；密码只在本地填写。`DAV_UNAVAILABLE` 指运行环境或可选依赖缺失，不表示账户不存在；不要自行安装或降级。
- `event_list` 传明确集合、秒精度起止时间（基本 UTC 或带 Z／偏移的 ISO 8601）及显式 `timeZone`，若账户已配置时区可省略调用时区。未有时区依据时澄清，不采用主机时区或把旧工作流默认值自动带入。实际会读取所选日历全部事件资源，再按调用时区和窗口在本地展开过滤，不发送服务端时间窗以避免 floating 时区差异漏项；大日历可能因读取量或库预算而明确失败，缩小窗口不一定减少网络量。返回按发生时间展开的日程；`recurrenceId` 是发生身份，`storedRecurrenceId` 才是已存储例外的完整逻辑行。读取主件时省略例外参数；不要把合成实例冒充独立存储组件。
- 待办／日记列表只列存储组件，不展开重复规则。联系人列表返回姓名、邮件、电话等摘要，不冒充旧多字段搜索。首版没有分页，结果过大返回明确错误，不把部分结果当作完整列表或全局不存在的证明。
- 详情使用列表的实际 `resourceUrl`，日历还需 UID 与可选完整例外逻辑行；不要拼 UID 路径。详情默认结构化属性，只有任务需要原文才传 `raw: true`。同时核对 `ok` 和错误标记，按任务最小范围输出，不展示整本数据。
- 本节仅适用于实际已加载的原生工具。旧 MCP 尚未停用；业务写入或旧搜索须另行确认任务范围与工具入口，不做自动写入回退。

## 旧 MCP 工具发现与连接

- 先通过当前宿主的工具发现入口查找 `tsn__calendar_list`、`tsn__calendar_event_list`、`tsn__contacts_search` 等实际工具，再读取其参数 schema。工具可能带服务前缀；以发现的完整名称调用，不猜测名称或参数，不把描述中提及的其他工具视为已经可用。
- 在 Pi codemode 中可用 `searchTools('tsn__calendar_list', { limit: 3 })` 发现工具，必要时用 `describeTool()` 查看参数，再调用实际返回的 `tools.<完整工具名>(...)`。不得搜索或输出凭据。
- 提示账号未连接时，可调用 `dav_reconnect` 使用已有配置重连；已知目标账号时显式指定，避免无故重连全部账号。重连后重新查询目标目录或数据；连接成功、发现目录成功和读取真实数据是不同证据。
- 认证失败立即停止，不反复尝试，不索取或读取保存的密码，也不改用 `dav_connect` 绕过失败。配置缺失、权限不足或工具不可用时明确报告阻塞，不自行安装、登录或修改 MCP 配置。
- 同时检查工具错误标记及文本结果；不能仅因调用正常返回就断言成功，未连接或业务错误也可能出现在文本中。

## 旧 MCP 日历查询

1. 先调用 `calendar_list`，确认实际账号、日历名称和路径。不要硬编码个人目录，也不要将 calendar home 当作具体日历路径。
2. 未指定时区时使用 `Asia/Shanghai`；根据当前真实日期将“今天、明天、下周”等转换为具体起止日期。“下周”默认目标周周一 `00:00` 至再下一周周一 `00:00`，即目标周周一至周日；若上下文有其他含义，先澄清。调用时用带时区偏移的 ISO 8601 时间，并在结果中说明具体范围及所用时区。
3. 调用 `calendar_event_list`，必传明确的 `start`、`end`。整天查询从当天 `00:00:00+08:00` 到次日 `00:00:00+08:00`，避免用 `23:59:59` 漏掉小数秒；不臆测服务端边界是否包含，必要时核对返回的边界事件。指定日历时使用发现的账号和路径。当前实现中，传 `account` 却省略 `calendar` 只查询该账号的第一个日历，与工具描述的范围不一致；需要覆盖多个日历时，按发现结果逐个显式传 `account` 和 `calendar`，分别检查结果，不依赖省略参数的聚合查询（它可能跳过部分失败）。不把默认主日历当作全部日历。
4. 先读取列表摘要，仅在完成任务确有必要且存在相应工具时再取单项详情。注意全天、跨天、重复事件及其例外；不要未经核验把重复规则当作已展开的每次发生记录，也不要把局部列表当作完整空闲证明。
5. 查询为空时说明查了哪些日历及哪个时间范围。寻找近期安排或做只读实测时，可合理扩大到前后数周，明确区分各次结果；用户只问某一天时不为证明服务器有数据而无故扩查。不得把“当天无事件”说成“服务器没有数据”。

## 旧 MCP 联系人查询

- 已有姓名、邮箱或电话线索时优先 `contacts_search`；确实需要浏览列表或做一次只读能力验证时用 `contacts_list`。需要单项详情时，先确认实际存在的工具及目标 UID。
- 当前搜索会读取地址簿后在本地按姓名、邮箱、电话、组织或备注做不区分大小写的子串筛选，不是廉价的服务端索引查询。避免连续试探大量关键词或反复拉取整本地址簿；先利用已返回的结果，只有线索实质变化才再查询。
- 账号与地址簿参数按实际 schema 选择；默认主地址簿不代表所有地址簿。查不到时说明查询线索和范围，不断言联系人不存在于整个服务器。
- 同名或多个匹配结果时，只展示区分目标所需的少量字段；涉及写入则先请用户确认，不能自行挑选。

## 写入授权与核验

- 查询可直接执行；创建、修改和删除日程或联系人，必须有用户针对该动作的明确授权。“实测工具”“检查连接”或本技能本身都不是业务写入授权，不为验收创建再删除测试数据。
- 操作前查询现状，确认账号、具体日历或地址簿、目标 UID、时间与时区，以及用户要求变更的字段。存在重名、重复事件、重复联系人、时间歧义或周期事件单次／整组范围不明时，先询问，不误改其他数据。
- 新建前在相关时间范围或联系人线索内核对是否已有目标。修改只传明确要求改变的字段；省略字段与空字符串可能含义不同，不用猜测值填满参数。删除前精确定位目标，不仅凭名称执行，也不依赖跨目录模糊搜索。
- 周期事件、待办或日志类能力，仅在用户确有需求、实际工具支持且获得对应授权时使用；不把日程工具的能力推定为其他类型也支持。
- 写入返回后，在授权范围内按实际可用查询工具回读核对。请求失败或结果不明时先查询，避免重复创建或重复执行；未确认结果就报告“未确认”，不得声称成功或自动补偿删除。

## 隐私与结果汇报

- 只展示完成任务所需的信息，不倾倒整本通讯录或日程。只读实测优先输出查询范围、数量或成功／失败摘要，不展示无关正文；使用 codemode 时在当前调用内处理并精简输出，不把原始工具结果整段 `text()` 回显。
- 不把凭据、联系人正文或日程正文写入 `store`、日志、额外文件、代码仓库或记忆条目；也不在示例中固化真实姓名、电话、邮箱、UID 或个人目录。
- 分开汇报连接、目录发现、真实数据读取和写入结果；列出失败及未验证项。空结果不等于故障，也不证明有数据；只读成功不代表创建、修改、删除或周期处理已经通过验收。
